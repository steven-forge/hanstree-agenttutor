# /agents 모델 카탈로그 자동 갱신

## 무엇을 하나

매일 06:35(KST, GitHub 스케줄은 지연 가능)에 `scripts/update_agent_models.py`가
Claude, Codex, Gemini, Grok, DeepSeek, Muse 6개 제공사의 공식 공개 카탈로그를
조회해 `data/agent-models.json`을 갱신하고 master에 커밋·푸시한다(이후 Vercel 자동 배포).

- 새로 게시된 일반 텍스트/코딩 모델은 공식 상세 문서에서 정확한 모델 ID가
  확인된 경우에만 추가한다. 가격·사양·effort 등은 명시적으로 파싱된 값만
  기록하고, 확인되지 않은 값은 `공식 미확인`(문자열) 또는 `null`로 남긴다.
- 새 모델은 같은 계열(family) 안에서 기존 모델보다 앞에 삽입된다(계열 판정은
  모델 ID의 숫자 버전 토큰을 제거한 휴리스틱이며, 완벽하지 않을 수 있다).
  새 계열은 목록 앞에 표시한다. 에이전트별 표시 6개, 전체 비교 선택 5개 제한은 유지한다.
- 제공사별 목록 조회 실패/빈 카탈로그는 실패로 기록하고 기존 모델 데이터를
  그대로 보존한다. 개별 모델 상세 조회/파싱 실패는 `partial`로 기록되며
  기존 데이터는 보존하고 해당 모델은 baseline에 넣지 않아 다음 실행에서
  재시도된다. 일부 제공사가 실패해도 나머지 제공사는 정상 갱신된다.
- `data.checked_at`/`unit_note`의 날짜는 6개 제공사가 모두 성공한 "전체 성공"
  실행에서만 앞당긴다. 6개 모두 실패하면 전체 상태는 `failure`, 일부만
  실패/부분실패면 `partial`이다.
- `released_at`은 "Released"/"Launched" 문맥의 날짜만 인정하며, 문서에 섞인
  knowledge-cutoff나 경로상의 일반 날짜는 채택하지 않는다(불명확하면 필드
  자체를 생략).
- `effort_levels`는 공식 문서에서 명시적으로 확인되지 않으면 필드를 생략한다
  (필드 없음 = 미확인, 빈 배열 `[]` = "지원 안 함"이 명시적으로 확인된 경우).

## 상태 필드 (`data/agent-models.json` → `auto_update`)

- `last_checked_at`: 가장 최근 실행(성공/부분실패 무관) 시각.
- `last_successful_check_at`: 6개 제공사 모두 성공한 가장 최근 시각.
- `providers.<slug>`: `{ checked_at, status, discovered_ids, error? }`.
  `discovered_ids`는 지금까지 확인된 카탈로그 ID의 누적 집합으로, 첫 실행 시
  기존 수동 검증 모델까지 부트스트랩해 과거 카탈로그가 한꺼번에 UI에
  추가되지 않도록 한다.

`/agents` 페이지 왼쪽 하단에 실제 마지막 조회 시각과 매일 조회 예정 시각을
한국 시간으로 표시한다. 실패가 있으면 해당 제공사와 마지막 전체 성공 시각을
함께 표시한다. 첫 조회가 실패하면 성공 기록을 만들어 표시하지 않는다.

## 로컬 점검

```
python3 scripts/update_agent_models.py --self-check
```
네트워크 접근 없이 파서·삽입 순서·실패 시 데이터 보존·최초 실행(bootstrap)·
신규 모델 추가(idempotency 포함)·detail 실패 후 재시도 동작을 검증한다.
실제 실행(`python3 scripts/update_agent_models.py`)은 네트워크가 필요하며
모델 JSON과 조회 상태를 갱신한다. 배포 전 초기 조회에도 같은 명령을 사용한다.

자동 실행은 `.github/workflows/update-models.yml`이 담당한다. 매일 06:35 KST,
수동 실행, 수집 스크립트·워크플로 변경 시에 실행한다. 데이터 변경 커밋으로는
다시 실행하지 않는다. 조회 후 빌드를 통과해야 모델 데이터만 커밋·푸시한다.
일부 조회가 실패해도 보존된 데이터와 실패 상태를 게시하고 작업 결과는 실패로 남긴다.

## 알려진 한계

- 계열(family) 판정은 ID 토큰 기반 휴리스틱이라 `deepseek-v4-pro` →
  `deepseek-v5-pro`처럼 버전 접두사가 바뀌면 다른 계열로 오판될 수 있다.
- 음성·이미지 생성 전용 모델, 비공개 모델은 현재 비교 범위에 포함하지 않는다.
- 공식 문서 구조가 달라져 모델이나 요금을 읽지 못하면 기존 자료를 보존하고
  조회 확인이 필요한 상태로 남긴다. 새 모델의 미확인 값은 추정하지 않는다.
- 기존 한국어 특징·입력 유형·앱 구독 요금제 안내는 수동 검토 자료를 유지한다.
  자동 조회 시각이 모든 앱 요금제·문구의 재검토 시각을 뜻하지는 않는다.
- DeepSeek 가격표는 rowspan/colspan을 실제 HTML 속성이 아니라 "행 끝
  N개(모델 수)열이 모델별 값" 휴리스틱으로 복원한다. 표에 모델이 추가/삭제돼
  열 개수가 바뀌면 재검증이 필요하다.
- Gemini의 기간 한정 가격은 조회 날짜에 유효한 표준 요금으로 선택한다.
  캐시 저장 시간당 요금은 캐시 읽기 토큰 단가에 섞지 않는다.
- GitHub 예약 실행은 지연될 수 있으며, 실행·빌드·배포 서비스 장애가 있으면
  페이지가 새로 갱신되지 않을 수 있다. 표시된 마지막 조회 시각으로 확인한다.
