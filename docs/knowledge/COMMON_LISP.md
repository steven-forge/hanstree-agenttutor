# Common Lisp: 코드를 실행하며 확장하는 프로그래밍 언어

확인일: 2026-10-07 (KST)

## 1. 질문과 핵심 답변

Common Lisp은 무엇이고, 왜 괄호가 많고 코드를 실행하며 확장하는 언어라고 하나요?

Common Lisp은 표준으로 정해진 Lisp 계열 프로그래밍 언어입니다. (+ 2 3)처럼 연산 이름을 앞에 쓰고, 코드를 새로운 코드로 바꾸는 매크로와 객체 시스템을 지원합니다.

대화형 환경인 REPL에서 작은 코드를 실행하고 결과를 보며 함수를 고쳐 나갈 수 있습니다.

## 2. 쉬운 설명

계산기에 식을 넣으면 바로 답이 나오듯, Common Lisp도 식을 입력하면 결과를 돌려줍니다. 이 입력-평가-출력의 반복 화면을 REPL이라고 부릅니다.

예를 들어 (+ 2 3)을 넣으면 5가 나올 것으로 예상합니다. (* 2 (+ 3 4))는 안쪽 (+ 3 4)가 7이 되고 2를 곱해 14가 될 것으로 예상합니다.

함수도 같은 방식으로 만듭니다. (defun double (x) (* 2 x))로 정의하면 (double 7)은 14가 될 것으로 예상합니다.

이 값들은 예상 결과이며, 이 문서를 쓰며 직접 실행한 결과가 아닙니다.

보통 괄호 안 첫 항목은 연산이나 이름이고 나머지는 인수입니다. 다만 모든 괄호가 함수 호출은 아닙니다. 매크로, 특수 형식, 자료를 나타내는 괄호도 있습니다.

### 용어: REPL·매크로·CLOS·구현체

REPL은 입력한 식을 읽고(Read), 계산하고(Eval), 결과를 보여 주는(Print) 일을 되풀이하는 환경입니다.

매크로는 코드 모양을 받아 새로운 코드 모양으로 바꿔 주는 장치입니다. 단순한 글자 바꾸기가 아니라 코드 구조 전체를 다룹니다.

CLOS는 Common Lisp의 객체 시스템입니다. 일반 함수는 인수의 종류에 따라 실행할 방법(메서드)을 고르며, 호출 문법은 일반 함수와 같습니다.

구현체는 언어를 실제로 실행하는 프로그램입니다. SBCL은 무료 오픈소스 Common Lisp 컴파일러·런타임 구현체의 하나입니다.

## 4. 관련 언어와 비교

Common Lisp, Clojure, Python은 모두 대화형으로 시험해 볼 수 있지만 성격이 다릅니다.

Clojure는 Lisp 계열이어도 Common Lisp과 다른 언어입니다. 아래 표는 공식 설명 범위의 비교이며 성능 우열을 말하지 않습니다.

Common Lisp·Clojure·Python 비교(공식 자료 기반, 성능 비교 아님)

| 비교 항목 | 특징 | 알아둘 점 |
| --- | --- | --- |
| Common Lisp | ANSI 표준 Lisp 계열 언어입니다. 컴파일을 지원하고, 매크로와 객체 시스템(CLOS)을 갖추고 있습니다. | 언어와 구현체가 구분됩니다. SBCL은 구현체의 하나입니다. |
| Clojure | JVM 위에서 동작하는 Lisp 계열 언어로, 함수형 프로그래밍과 기본 불변 자료구조에 중점을 둡니다. | Common Lisp과 다른 언어이며 코드 호환을 보장하지 않습니다. |
| Python | 동적 타이핑, 객체지향을 지원하고 스크립팅과 빠른 개발에 쓰입니다. 대화형 환경도 지원합니다. | 괄호 중심 문법이 아니며, REPL은 Common Lisp만의 기능이 아닙니다. |

코드 모양 자체를 다루는 매크로와 표준화된 객체 시스템에 관심이 있다면 Common Lisp을 살펴볼 수 있습니다. JVM 환경과 불변 자료구조가 중요하다면 Clojure를, 빠르게 작성하는 범용 스크립트가 목적이라면 Python을 볼 수 있습니다.

이 선택 기준은 확인한 설명에 따른 해석이며, 같은 조건에서 성능을 측정한 결과는 아닙니다.

## 5. 자세한 설명

Common Lisp은 하나의 제품이 아니라 표준으로 정해진 언어입니다. 공식 사이트는 ANSI 표준 Lisp 계열이며 컴파일을 지원하는 다중 패러다임 언어라고 소개합니다.

그 표준을 실제로 동작시키는 프로그램이 구현체입니다. SBCL이 대표적인 예이며, 언어와 구현체는 구분해서 이해해야 합니다.

REPL에서는 함수를 정의하고, 불러 보고, 고쳐 다시 정의하는 과정을 짧게 반복할 수 있습니다. 이것이 코드를 실행하며 키워 간다는 말의 뜻입니다.

다만 이 방식이 모든 서비스를 멈춤 없이 고칠 수 있다는 보장은 아닙니다. 실제 서비스 수정은 상태, 데이터, 운영 절차를 따로 고려해야 합니다.

매크로 설명에서 기준이 되는 표준 문서(HyperSpec)는 매크로가 코드 형식과 환경을 받아 새 형식을 만들고, 그 결과가 원래 코드 대신 평가된다고 설명합니다.

그래서 매크로는 반복되는 코드 모양에 이름을 붙여 새로운 문법처럼 쓰게 해 줍니다. 언제 어떻게 펼쳐지는지는 실행 방식에 따라 다를 수 있어, 항상 컴파일 때만 일어난다고 단정하면 안 됩니다.

CLOS는 객체를 중심으로 한 기능을 제공합니다. 일반 함수는 하나 이상의 인수의 클래스나 동일성에 따라 메서드를 선택합니다.

그래서 호출하는 쪽에서는 보통 함수를 부르듯 쓰면서, 인수 종류에 따라 다른 동작을 붙일 수 있습니다.

Clojure도 Lisp 계열이지만 Common Lisp과는 다른 언어입니다. Clojure 공식 설명은 JVM 위에서 함수형 프로그래밍과 기본 불변 자료구조에 중점을 둔다고 밝히며, 코드 호환을 보장하지 않습니다.

Python도 대화형 환경을 지원합니다. 공식 튜토리얼은 동적 타이핑, 객체지향, 스크립팅과 빠른 개발에 적합한 언어로 설명합니다. REPL이 Common Lisp만의 기능은 아닙니다.

이 문서는 공식 자료를 정리한 설명입니다. 가격, 최신 버전, 성능 우열, 인기도는 다루지 않으며, 예시 코드를 실행해 본 결과도 아닙니다.

## 6. 헷갈리기 쉬운 점

- 괄호 안 첫 항목이 연산이고 나머지가 인수라는 설명은 보통 함수 호출에 해당합니다. 매크로, 특수 형식, 자료를 나타내는 괄호도 있어 모든 괄호가 함수는 아닙니다.

- REPL로 함수를 고쳐 가며 개발할 수 있어도 모든 서비스를 멈춤 없이 수정할 수 있다는 보장은 아닙니다.

- 매크로는 단순한 문자열 치환이 아니라 코드 구조를 받아 새 코드를 만드는 장치입니다. 항상 컴파일 때만 작동한다고 단정하면 안 됩니다.

- Common Lisp은 AI 전용 언어도, 인터프리터 전용 언어도 아닙니다. 컴파일을 지원하는 범용 언어입니다.

- Common Lisp은 언어이고 SBCL은 구현체입니다. Clojure는 같은 Lisp 계열이지만 다른 언어이며, Python에도 대화형 환경이 있습니다.

## 8. 이해도 확인

보기를 고르면 즉시 채점됩니다. 오답은 바로 다른 보기를 다시 선택할 수 있으며, 정답을 맞히면 해설을 확인합니다.

점수는 각 문항의 첫 선택 기준입니다. 응시 기록은 저장하지 않습니다.

### 문제 1. Common Lisp 코드 (+ 2 3)에서 괄호 안 첫 항목 +와 나머지 2, 3은 보통 어떻게 읽나요?

1. 2와 3을 먼저 더한 뒤 +를 이름표로 붙인다
2. 첫 항목 +는 할 일(연산)이고 2와 3은 그 재료(인수)다
3. 세 항목은 순서와 상관없이 모두 같은 자료다
4. 첫 항목은 주석이고 나머지가 실행된다

정답: 2번

해설: 보통 함수 호출에서는 괄호 안 첫 항목이 연산이나 이름이고 나머지가 인수입니다. 다만 매크로나 특수 형식처럼 읽는 방식이 다른 괄호도 있어 모든 괄호가 함수는 아닙니다.

### 문제 2. 개발자가 REPL에서 (defun double (x) (* 2 x))를 입력해 함수를 만든 뒤 (double 7)을 불러 봅니다. REPL의 주된 목적은 무엇인가요?

1. 프로그램을 설치 파일로 한 번에 묶는다
2. 코드를 사람이 읽지 못하는 형태로 바꾼다
3. 서비스를 항상 멈춤 없이 고칠 수 있게 보장한다
4. 식을 입력하고 결과를 보며 함수를 정의하고 고치는 과정을 반복한다

정답: 4번

해설: REPL은 입력-평가-출력을 반복하는 환경입니다. 함수를 다시 정의하며 개발할 수 있지만, 모든 서비스의 무중단 수정을 보장하는 것은 아닙니다.

### 문제 3. Common Lisp의 매크로에 대한 설명으로 올바른 것은 무엇인가요?

1. 코드 형식을 받아 새로운 코드 형식을 만들고 원래 코드 대신 평가되게 한다
2. 코드 안의 글자를 단순히 찾아 바꾸는 기능이다
3. 항상 컴파일 때만 작동하고 그 외에는 작동하지 않는다
4. 객체의 종류에 따라 실행할 메서드를 고르는 기능이다

정답: 1번

해설: 매크로는 코드 형식과 환경을 받아 새 형식을 만들고, 그 결과가 원래 코드 대신 평가됩니다. 단순 문자열 치환이 아니며, 항상 컴파일 때만 작동한다고 단정할 수 없습니다. 메서드 선택은 CLOS 일반 함수의 역할입니다.

### 문제 4. 한 개발자가 "저는 SBCL로 Common Lisp 코드를 실행합니다"라고 말했습니다. 이 말에서 SBCL의 위치는 무엇인가요?

1. Common Lisp을 대체하는 새로운 언어
2. Clojure를 실행하는 JVM 도구
3. Common Lisp을 실행하는 구현체의 하나
4. Common Lisp 표준을 만든 공식 기관

정답: 3번

해설: Common Lisp은 표준으로 정해진 언어이고, SBCL은 그 언어를 컴파일하고 실행하는 무료 오픈소스 구현체입니다. 언어와 구현체는 구분해야 합니다.

### 문제 5. Common Lisp 코드를 Clojure 프로젝트에 그대로 붙여 넣으려 합니다. Clojure와 Common Lisp의 관계에 대해 올바른 것은 무엇인가요?

1. 같은 언어의 다른 이름이라 그대로 동작한다
2. 같은 Lisp 계열이지만 서로 다른 언어이며 코드 호환이 보장되지 않는다
3. Clojure는 Common Lisp의 구버전이다
4. Clojure는 Common Lisp 코드를 자동으로 번역해 실행하는 도구다

정답: 2번

해설: Clojure는 JVM에서 함수형 프로그래밍과 기본 불변 자료구조에 중점을 둔 별개의 Lisp 언어이며, Common Lisp과의 코드 호환을 보장하지 않습니다.
