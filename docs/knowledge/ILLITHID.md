# Illithid: 여러 AI 코딩 도구의 설정을 한곳에서 관리하기

확인일: 2026-10-07 (KST)

## 1. 질문과 핵심 답변

Illithid는 무엇이고, 여러 AI 코딩 도구의 설정을 어떻게 한곳에서 관리하나요?

Illithid는 Claude Code, Codex 같은 여러 AI 코딩 도구의 규칙·스킬·서브에이전트·MCP 설정을 공통 라이브러리 한 곳에서 고치고, 고른 도구의 설정 파일로 반영해 주는 macOS 앱입니다. 모델을 실행하거나 요청을 중계하는 제품이 아니라서, 기존 도구는 그대로 사용합니다.

반영하기 전에 바뀌는 내용을 미리 보여 주고, 덮어쓰거나 지우는 원본은 백업합니다.

## 2. 쉬운 설명

같은 규칙을 Claude Code용 파일에도, Codex용 파일에도 복사해 두었다고 해 봅시다. 규칙을 하나 고칠 때마다 도구 수만큼 파일을 열어 같은 수정을 반복해야 합니다.

Illithid에서는 공통 라이브러리에서 한 번 고치고 반영할 도구를 고릅니다. 변경 미리보기를 확인한 뒤 적용하면 각 도구가 읽는 고유 파일에 맞는 형식으로 기록됩니다.

가령 “답변은 한국어로 작성한다”라는 규칙을 여러 도구의 설정 파일에 전달할 수 있습니다. 같은 설정을 전달해도 모델의 답변이 항상 같아지는 것은 아닙니다.

### 용어: 공통 라이브러리·스킬·서브에이전트·MCP·hooks

공통 라이브러리는 여러 도구가 함께 쓸 설정을 모아 둔 한 곳입니다. 규칙은 AI에게 주는 지침이고, 스킬은 특정 작업의 방법을 담은 묶음입니다.

서브에이전트는 일부 일을 맡기는 보조 AI입니다. MCP는 AI 도구를 외부 도구·서비스에 연결하는 방식이고, hooks는 정해진 때에 스크립트나 확인 규칙을 실행하는 장치입니다.

권한은 명령을 허용할지, 물을지, 막을지를 정한 설정입니다. Illithid는 이 설정을 각 도구의 설정 파일에 써 줄 뿐이고, 실제 실행 여부는 각 도구가 판단합니다.

## 4. 비슷한 설정 관리 방식과 비교

Illithid는 앱 화면에서, Ruler는 파일과 명령어를 통해 공통 설정을 관리합니다. 도구별 수동 설정은 각 도구의 설정을 직접 관리하는 방법입니다.

Ruler도 규칙과 MCP 외에 실험적 스킬·서브에이전트 배포를 지원합니다. 스킬은 기본으로 켜져 있고 서브에이전트 배포는 기본으로 꺼져 있습니다.

Illithid·Ruler·도구별 수동 설정 비교(공식 자료 기반, 성능 비교 아님)

| 비교 항목 | 관리 방식 | 주로 맞는 상황 |
| --- | --- | --- |
| Illithid | 앱의 공통 라이브러리에서 고치고 도구를 골라 미리 본 뒤 적용합니다. hooks와 허용·질문·차단 권한도 함께 다룹니다. macOS 앱입니다. | 여러 도구의 설정을 앱 화면에서 한곳에 모아 두고 싶은 Mac 사용자 |
| Ruler | .ruler 폴더의 파일을 ruler apply 명령으로 각 도구의 파일에 배포합니다. --dry-run으로 미리 볼 수 있고, 규칙과 MCP, 실험적 스킬(기본 켜짐)·서브에이전트(기본 꺼짐)를 다룹니다. | 설정을 프로젝트 파일과 명령줄로 다루는 방식이 편한 경우 |
| 도구별 수동 설정 | 각 도구의 고유 파일을 직접 열어 고칩니다. | 도구가 한두 개이고 바꿀 일이 드물어 반복 부담이 작은 경우 |

앱 화면에서 여러 도구를 함께 관리하려면 Illithid를, 프로젝트 파일과 명령어 중심으로 설정을 배포하려면 Ruler를 살펴볼 수 있습니다. 도구가 적고 설정 변경이 드물면 수동 관리로도 충분할 수 있습니다.

이 선택 기준은 확인한 작동 방식에 따른 해석이며, 같은 조건에서 성능을 측정한 결과는 아닙니다.

## 5. 자세한 설명

공식 README가 설명하는 관리 대상은 규칙, 스킬, 서브에이전트, MCP 서버, hooks, 권한입니다. 각 도구가 받을 항목은 사용자가 고릅니다.

문서가 거론하는 도구는 Claude Code, Codex, OpenCode, Gemini CLI, GitHub Copilot, Grok CLI 여섯 가지입니다. 모든 기능을 여섯 도구가 똑같이 지원하는 것은 아닙니다.

hooks는 Claude Code, Codex, Gemini CLI, GitHub Copilot, Grok CLI에서 각 도구의 형식으로 실행됩니다. 셸 명령 권한은 Claude Code, Codex, Gemini CLI, GitHub Copilot에 적용되고, MCP 서버의 도구별 권한은 Claude Code, Codex, Gemini CLI, OpenCode에 적용됩니다.

허용·질문·차단 설정은 파일로 기록되고 실행은 각 도구가 합니다. Illithid가 독립된 보안 장벽이나 승인 에이전트 역할을 하는 것은 아닙니다.

처음 실행하면 이미 쓰던 설정을 가져올 수 있습니다. 가져온 원본은 Illithid가 관리를 시작하기 전에 백업됩니다.

사용량 화면은 내 컴퓨터의 세션 로그를 읽어 요청 수, 토큰 사용량, 응답 시간 중앙값을 보여 줍니다. 비용은 공개된 API 단가로 환산한 금액입니다. 실제 구독 청구액이나 남은 사용량이 아닙니다.

도구와 기간으로 걸러 모델·추론 강도 조합을 비교할 수 있지만, 작업의 종류와 길이가 다른 기록을 그대로 비교하면 모델 성능 비교가 되지는 않습니다. 사용 패턴을 살펴보는 자료로 활용합니다.

부가 기능으로 지난 대화 검색·재개(Sessions), 에이전트 메모리를 검토해 공통 라이브러리로 올리는 기능(Memory), 에이전트가 만든 결과물 보기(Artifacts), 규칙·스킬·MCP 서버를 찾는 Market, 분리된 작업 공간과 Git 백업(Workspaces & backup)이 있습니다.

확인한 최신 공개판은 v0.3.5입니다. 2026년 10월 6일 오전 10시 21분(한국 시간)에 게시됐고, macOS 12 이상의 Apple Silicon과 Intel을 지원합니다. 라이선스는 MIT이며 앱은 한국어를 지원합니다.

지금 배포되는 것은 macOS용뿐입니다. 비밀값을 macOS 키체인에 저장하기 때문입니다. 

Mac에서는 공식 릴리스의 DMG를 받거나 Homebrew로 설치할 수 있습니다. 처음에는 기존 설정을 가져오고 사용할 도구를 고른 뒤, 반영할 변경을 미리 확인합니다.

모델 API를 호출하지 않는다고 해서 완전 오프라인은 아닙니다. 업데이트 확인, Market, Git 원격 백업, 선택적인 GitHub 백업 로그인 연결에서 외부 통신이 생길 수 있습니다.

Market과 업데이트 확인은 설정에서 끌 수 있다고 안내됩니다. 비밀값은 macOS 보안 저장소에 보관됩니다.

v0.3.5는 GitHub 로그인으로 비공개 백업 저장소를 만드는 흐름을 안내합니다. 개인 GitHub 계정 기준이며, 조직과 Enterprise는 이 로그인 흐름을 지원하지 않습니다. 이미 있는 원격 저장소 주소를 연결하는 방법은 별개입니다.

앱을 삭제해도 이미 기록된 일반 설정 파일은 남아 각 도구가 계속 동작합니다. 한 도구의 동기화만 끄고 싶다면 설정에서 끄고, 미리보기에서 제거될 항목을 확인합니다.

교체되거나 삭제된 파일은 백업 폴더로 옮겨지고, 오래된 백업은 기본 30일 뒤 휴지통으로 이동합니다(기간은 바꿀 수 있습니다). 영구 보관을 보장하는 것은 아닙니다.

이 문서는 공식 저장소와 릴리스 안내를 정리한 설명이며, Illithid를 설치하거나 실행해 본 결과가 아닙니다.

## 6. 헷갈리기 쉬운 점

- Illithid는 모델을 실행하거나 요청을 중계하지 않습니다. 기존 AI 코딩 도구를 계속 사용하며, Illithid는 그 도구의 설정 파일을 관리합니다.

- 여섯 도구가 모든 기능을 똑같이 지원하지 않습니다. hooks, 셸 명령 권한, MCP 권한마다 지원하는 도구가 다릅니다.

- 사용량 화면의 비용은 공개 API 단가로 환산한 금액입니다. 실제 구독 청구액이나 남은 사용량이 아니며, 모델 우열을 보여 주는 실험 결과도 아닙니다.

- 모델 API를 호출하지 않아도 완전 오프라인은 아닙니다. 업데이트 확인, Market, Git 원격 백업 같은 기능은 외부와 통신할 수 있습니다.

- 허용·질문·차단 설정은 각 도구가 실행합니다. Illithid가 별도의 보안 장벽이나 승인 에이전트가 되는 것은 아닙니다.

## 8. 이해도 확인

보기를 고르면 즉시 채점됩니다. 오답은 바로 다른 보기를 다시 선택할 수 있으며, 정답을 맞히면 해설을 확인합니다.

점수는 각 문항의 첫 선택 기준입니다. 응시 기록은 저장하지 않습니다.

### 문제 1. 같은 규칙을 Claude Code와 Codex의 파일에 각각 복사해 쓰던 개발자가 Illithid를 쓰기로 했습니다. Illithid가 맡는 핵심 역할은 무엇인가요?

1. 개발자 대신 코드를 작성하는 새로운 AI 모델을 제공한다
2. 각 도구의 요청을 받아 모델 API로 전달하는 중계 서버가 된다
3. 공통 라이브러리의 설정을 고른 도구들의 고유 설정 파일에 반영한다
4. 각 도구의 실행 화면을 하나로 합쳐 동시에 작업하게 한다

정답: 3번

해설: Illithid는 공통 라이브러리에서 고친 설정을 선택한 도구의 고유 파일로 반영합니다. 모델을 실행하거나 요청을 중계하지 않고 기존 도구를 그대로 씁니다.

### 문제 2. 공통 라이브러리에서 규칙 하나를 고친 뒤 선택한 도구에 반영하려 합니다. 안내된 반영 방식은 무엇인가요?

1. 바뀌는 내용을 미리 보고 확인한 뒤 적용한다
2. 수정하는 즉시 모든 도구의 파일을 조용히 덮어쓴다
3. 적용을 마친 뒤에 바뀐 내용을 보여 준다
4. 도구마다 설정 화면에 같은 내용을 따로 입력하게 한다

정답: 1번

해설: Illithid는 적용 전에 변경 내용을 미리 보여 줍니다. 교체되거나 삭제되는 파일은 백업 폴더로 옮겨집니다.

### 문제 3. Illithid의 사용량 화면에 API 환산 비용이 표시됐습니다. 이 숫자는 무엇을 나타내나요?

1. 구독 서비스가 이번 달 실제 청구한 금액
2. 다음 달 구독 갱신에 필요한 결제 금액
3. 구독 요금에서 사용분을 뺀 잔여 금액
4. 기록된 토큰 사용량에 공개 API 단가를 적용한 금액

정답: 4번

해설: 비용은 공개된 API 단가로 환산한 금액입니다. 실제 구독 청구액이나 남은 사용량이 아니며, 모델 우열을 보여 주는 실험 결과도 아닙니다.

### 문제 4. Illithid가 지원하는 코딩 도구를 선택했습니다. 이 도구에서 훅과 명령 권한 설정을 모두 쓸 수 있는지 확인하려면 무엇을 봐야 하나요?

1. 도구가 전체 지원 목록에 있으면 모든 기능을 지원한다고 본다
2. 훅과 명령 권한 각각의 지원 도구 목록을 확인한다
3. 앱이 한국어를 지원하면 모든 기능을 지원한다고 본다
4. 같은 운영체제에서 실행되면 모든 기능을 지원한다고 본다

정답: 2번

해설: 앱의 전체 지원 도구 목록과 기능별 지원 목록은 다릅니다. 훅, 셸 명령 권한, MCP 권한 각각의 지원 대상을 확인해야 합니다.

### 문제 5. Illithid는 어떤 모델 API에도 요청을 보내지 않는다고 안내됩니다. 외부 통신에 대한 올바른 이해는 무엇인가요?

1. 모델 API를 쓰지 않으므로 모든 외부 통신이 없다
2. 코드와 프롬프트는 반드시 Illithid의 모델 서버를 거친다
3. 모델 API는 쓰지 않아도 마켓·업데이트·원격 백업은 통신할 수 있다
4. 외부 통신은 모델 API에만 허용되고 다른 기능에는 없다

정답: 3번

해설: 모델 API를 호출하지 않는 것과 완전 오프라인은 다릅니다. 업데이트 확인, Market, Git 원격 백업, 선택적 GitHub 백업 로그인 연결에서 외부 통신이 생길 수 있습니다.
