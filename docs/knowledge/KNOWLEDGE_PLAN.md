# Explore — 구성 및 운영 계획

상태: 사용자가 메뉴명을 Explore로 확정하고 메뉴 추가를 요청했다. Explore 메뉴와 빈 문서 목록 화면을 로컬에 구현했고 빌드는 통과했다(v0.9.4). 운영 사이트 반영은 아직이다. 문서 작성·그림·조작 예제는 첫 문서 요청에 맞춰 이어서 구현한다.

## 1. 만들고 싶은 경험

궁금한 내용을 질문하면 핵심을 정리하고 쉬운 말과 예시로 설명한 문서 한 편을 만든다. 문서는 왼쪽 사이드 메뉴의 독립된 카테고리에 모으고, 목록에서 찾아 다시 읽을 수 있게 한다.

확정된 요구는 다음과 같다.

- 질문을 바탕으로 내용을 정리한다.
- 사전 지식이 없어도 이해할 수 있도록 설명한다.
- 질문의 주제를 문서 한 페이지로 보여준다.
- 문서를 목록으로 관리하고 왼쪽 메뉴에 하나의 카테고리를 추가한다.
- 질문은 지금의 놀이터 대화에서 한다.
- 문서가 완성되면 별도 게시 승인을 다시 받지 않고 바로 공개한다.
- 아래로 내려 읽는 문서에 쉬운 설명, 그림, 직접 조작하는 예제를 포함한다.
- ‘문서로 정리해 줘’라고 요청한 질문만 문서로 만든다.
- 문서 수정·제목 변경·공개 중단 등은 지금 대화에서 요청하면 반영한다.
- 새 메뉴 이름은 Explore로 확정했다.

처음에는 계획만 작성했으며, 후속 ‘Explore 로 메뉴 추가하자’ 요청에 따라 메뉴와 목록 진입 화면을 추가한다. 첫 문서의 주제는 아직 지정되지 않았다. 문서 내용은 사용자가 문서화를 요청한 질문으로 작성한다.

## 2. 현재 프로젝트에서 확인한 점

- `app/nav.ts`: 왼쪽 메뉴의 그룹과 상단 메뉴를 관리한다.
- `app/DocsSidebar.tsx`: 접이식 메뉴와 현재 문서 표시가 있다.
- `app/SiteHeader.tsx`: 같은 메뉴 데이터를 모바일 전체 메뉴에서도 사용한다.
- `app/learn/page.tsx`, `app/learn/[slug]/page.tsx`: 문서 목록, 개별 본문, 출처, 목차의 기존 화면이 있다.
- `app/glossary/GlossaryClient.tsx`: 검색과 분류 선택, 검색 결과가 없을 때의 안내 방식이 있다.
- `app/content.ts`: 프로젝트 안의 JSON 자료에서 콘텐츠를 읽는다.

이 구조를 활용해 새 목록과 문서를 추가할 수 있다. 확인한 소스 범위에서는 사이트 내 AI 질문 입력·문서 작성/수정·개인 보관을 위한 로그인 기능을 찾지 못했다. 질문과 관리 요청은 놀이터 대화에서 하기로 확정했으므로 사이트는 공개 문서를 읽고 찾는 공간으로 구성한다.

## 3. 화면 구성

메뉴 위치는 **Learn 다음 순서의 최상위 독립 카테고리**다. 기존 News·Learn과 같은 단계에 두어 기존 학습 과정과 질문에서 생긴 문서를 구별해 찾아볼 수 있게 한다. 상단 메뉴와 모바일 메뉴에도 같은 Explore 진입점을 연결한다.

이름은 **Explore**다. 다양한 질문을 그림과 조작 예제로 알아가는 공간이라는 의미다.

### 왼쪽 메뉴

- Explore
  - All Documents

문서는 전체 문서 목록에서 찾는다. 문서가 늘어도 메뉴가 계속 길어지지 않도록 한다. 개별 문서를 읽는 중에도 해당 카테고리가 펼쳐지고 현재 위치를 알아볼 수 있어야 한다.

### 목록 화면

이번 메뉴 추가에서는 등록 문서 0개와 ‘아직 등록된 문서가 없습니다.’ 안내를 표시한다. 다음 목록 기능은 실제 문서를 추가하는 작업에서 연결한다.

| 요소 | 역할 |
| --- | --- |
| 검색창 | 제목·요약·주제 태그로 문서 찾기 |
| 주제 선택 | 전체 또는 원하는 주제만 보기 |
| 문서 한 줄 | 제목, 짧은 설명, 주제, 수정일 표시 |
| 정렬 | 최근 추가된 문서부터 표시 |
| 문서 클릭 | 그 문서의 고유 주소로 이동 |
| 빈 화면 | 아직 문서가 없음과 검색 결과 없음을 구분해 안내 |

처음에는 큰 분류를 많이 만들지 않고, 실제 쌓이는 질문에 맞춰 간단한 주제 태그를 붙인다. 질문 범위는 AI에만 한정하지 않는 안으로 두되 사용자 답변에 따라 조정한다.

### 문서 화면

큰 화면에서는 기존 사이트처럼 왼쪽 메뉴, 가운데 본문, 오른쪽 목차로 배치한다. 휴대전화에서는 본문을 중심으로 보여주고 메뉴·목차를 접어서 사용한다.

한 페이지는 **아래로 내려 읽는 웹 문서 한 편**으로 확정했다. 본문 안에 설명 그림과 조작 예제를 넣어 읽기와 직접 확인하기가 이어지게 한다.

## 4. 문서 한 편의 작성 형식

| 순서 | 내용 | 작성 원칙 |
| --- | --- | --- |
| 1 | 제목과 원래 질문의 요지 | 무엇을 설명하는지 바로 드러낸다. 개인적인 대화 내용은 그대로 싣지 않는다. |
| 2 | 핵심 답변 | 처음에 2~3문장으로 답부터 제시한다. |
| 3 | 쉬운 설명 | 낯선 용어를 풀고 일상적인 비유를 붙인다. |
| 4 | 그림으로 이해하기 | 구조·과정·비교를 그림으로 보여주고 짧은 설명을 붙인다. |
| 5 | 직접 조작해 보기 | 선택 버튼·슬라이더·간단한 입력으로 조건을 바꾸고 결과를 확인한다. |
| 6 | 더 자세한 설명과 예시 | 조작 결과가 왜 달라지는지 설명하고 실제 상황과 연결한다. |
| 7 | 헷갈리기 쉬운 점 | 해당 주제에서 꼭 필요한 오해나 예외만 설명한다. |
| 8 | 출처와 확인일 | 조사에 사용한 원문과 언제 확인했는지 표시한다. |

쉬운 설명·그림·조작 예제는 기본 구성으로 둔다. 추가 비교표·오해 설명 등은 주제에 맞춰 조정한다. 제목 아래 짧은 요약만 읽어도 핵심을 알 수 있고, 더 궁금하면 본문을 이어서 읽게 한다.

예시 질문이 “AI는 왜 가끔 틀린 답을 할까?”라면 핵심 답변, 쉬운 비유, 답을 만드는 과정, 오류 예시, 확인 방법 순서로 구성한다. 이는 문서 구성 예시이며 실제 조사·작성한 문서는 아니다.

최신 정보가 필요한 주제는 작성할 때 원문을 확인한다. 확인된 사실·설명을 위한 비유·추정을 구별한다. 추가 설명을 요청받으면 기존 문서를 보완할지 별도 주제로 나눌지 먼저 판단한다.

### 그림과 조작 예제의 구체적인 구성

쉬운 설명 바로 다음에 그림을 배치하고, 그림 아래 조작부와 결과 설명을 둔다. 조작하면 그림과 결과 문장이 함께 바뀌도록 한다. 각 예제에는 처음 상태로 되돌리기를 제공한다.

| 주제 예시 | 그림 | 독자가 하는 조작 | 보여주는 변화 |
| --- | --- | --- | --- |
| 낮과 밤은 왜 생길까? | 태양, 지구, 관찰 지점 | 지구의 회전 위치를 슬라이더로 변경 | 관찰 지점이 밝은 쪽·어두운 쪽으로 이동하고 낮·밤 설명 변경 |
| 벽이 있으면 와이파이는 왜 약해질까? | 공유기와 기기 사이의 장애물 | 벽 추가·제거 | 설명용 신호 그림과 장애물 영향에 관한 설명 변경 |
| 질문을 구체적으로 하면 무엇이 달라질까? | 질문의 조건과 예시 답변 비교 | 대상·목적·원하는 형식 선택 | 미리 준비한 질문·답변 예시가 바뀌고 차이 설명 |

이 표는 화면 설계 예시이며 실제 구현·실험 결과가 아니다. 와이파이 예제는 실제 통신 속도를 예측하는 도구로 표시하지 않는다. 질문 예제의 답변은 미리 준비한 설명용 사례라고 표시한다.

그림에는 내용을 설명하는 글을 함께 제공한다. 조작부는 휴대전화 터치와 키보드로 사용할 수 있어야 하며, 색상만으로 결과를 구별하지 않는다. 설명을 위해 가정한 조건이 있으면 결과 옆에 표시한다.

## 5. 문서를 만들고 관리하는 흐름

확정된 흐름은 **놀이터 대화에서 질문과 함께 ‘문서로 정리해 줘’ 요청 → 필요한 자료 확인 → 쉬운 설명·그림·조작 예제 작성 → 완성 여부 확인 → 즉시 공개 → 대화에 실제 문서 주소 안내**다.

완성 즉시 공개하므로 게시 전 사용자에게 매번 승인을 다시 요청하지 않는다. 문서 제작 대상은 사용자가 ‘문서로 정리해 줘’라고 요청한 질문이다. 일반 질문은 대화로 답하며 작업 지시·인사·개인적인 대화를 임의로 공개 문서로 만들지 않는다.

문서의 새 작성·제목 변경·내용 보완·게시 중단은 놀이터 대화에서 요청하고 사이트에 반영하는 방식으로 확정했다. 예를 들어 ‘이 문서의 예시를 더 쉽게 바꿔 줘’, ‘제목을 바꿔 줘’, ‘이 문서는 공개를 중단해 줘’라고 요청할 수 있다.

문서의 완성 기준은 핵심 질문에 답하는 본문, 주제에 맞는 그림, 실제 작동하는 조작 예제, 필요한 출처·확인일을 갖춘 상태다. 미완성·오류 상태는 공개하지 않고 작업 상태를 알린다. 공개 페이지나 검색·배포 자료에 미완성 초안 본문을 포함하지 않는다.

같은 문서를 보완할 때는 기존 주소를 유지하고 수정일을 바꾼다. 조사나 게시가 실패하면 기존 공개 문서는 유지한다. 게시를 중단할 때는 사이트에서 내리는 일과 원본을 영구 삭제하는 일을 구분하고, 원본은 우선 보존한다.

완성된 문서는 개인 보관함이 아닌 공개 사이트에 게시한다. 문서에는 질문의 주제와 설명에 필요한 내용만 담는다.

## 6. 구현 구성

확정된 ‘놀이터 대화에서 작성하고 사이트에 즉시 공개’ 흐름에 맞춘 구성이다. 메뉴 추가 단계와 첫 문서를 추가할 단계를 구별한다.

| 구성 | 제안 |
| --- | --- |
| 전체 목록 주소 | `/explore` — 이번 메뉴 추가에서 연결 |
| 개별 문서 주소 | `/explore/문서-고유이름` — 첫 문서 추가 시 연결 |
| 문서 자료 | 기존 JSON 방식으로 문서별 제목·요약·태그·본문·출처·작성/수정일 보관 |
| 본문 표시 | 공통 문서 화면 하나에 각 문서 내용을 넣어 표시 |
| 설명 그림 | 주제에 맞는 도해와 설명문을 본문에 포함 |
| 조작 예제 | 주제별 필요한 조작과 결과 표시를 기존 React로 구현하고 문서에서 연결 |
| 검색 | 기존 용어사전의 검색·분류 방식을 활용 |
| 메뉴 | 기존 메뉴 자료에 한 카테고리 추가, 모바일과 선택 표시 연결 |
| 디자인 | 기존 글꼴·색상·여백·목차 구조 활용 |

문서마다 새로운 화면 코드를 만드는 방식은 피하고, 내용만 추가하면 목록과 상세 페이지에 함께 나타나게 한다. 목록과 본문은 동일한 문서 자료를 사용하고 문서의 고유 이름으로 연결한다. 출판할 자료는 확인된 원고만 사용한다.

조작 예제는 실제 질문에 필요한 유형부터 만들고 반복되는 유형만 재사용한다. 설명용 선택·계산·그림 변화는 브라우저 안에서 처리한다. 실제 AI를 다시 호출하는 체험이 필요하면 그때 용도와 비용·연결 방식을 별도로 정한다. 임의의 실행 코드를 문서 자료에 넣어 실행하지 않는다.

작성과 수정은 대화 요청에 따라 프로젝트의 문서 자료에 반영한다. 새 문서의 목록 등록, 같은 문서의 주소 유지, 공개 중단 상태가 실제 사이트에도 일치하도록 반영한다.

## 7. 진행 순서와 완료 기준

1. 질문 위치(지금 대화), 제작 기준(명시적 문서화 요청), 공개 방식(완성 즉시), 페이지 형태(쉬운 설명·그림·조작 예제가 있는 스크롤 문서), 관리 방식(대화 요청)은 확정했다.
2. 영어 메뉴 이름 Explore를 확정했고, 메뉴 추가 요청에 따라 메뉴와 빈 목록 화면을 연결한다.
3. 사용자가 ‘문서로 정리해 줘’라고 요청한 질문으로 설명 깊이와 그림·조작 예제 형태를 맞춘다.
4. 첫 문서의 목록·상세 화면·그림·조작 예제를 연결하고 완성 후 즉시 공개한다.

향후 구현 완료의 기준은 왼쪽 메뉴에서 목록으로 이동하고, 검색·주제 선택으로 문서를 찾고, 개별 주소에서 문서 한 편을 읽고 조작 예제를 사용할 수 있으며, 수정 후 같은 주소와 목록에 변경 사항이 반영되는 것이다. 휴대전화에서도 메뉴·본문·조작 예제를 이용할 수 있어야 한다. 공개 완료는 실제 문서 주소에 반영된 뒤 안내한다.

첫 문서의 질문이 정해지면 그림과 조작 예제의 구체적인 구성을 맞출 수 있다. 세부 디자인은 기존 사이트 스타일을 기본으로 한다.

## 검토 기록

기획 단계에서 팀장이 위에 적은 기존 소스를 읽고 현재 구조를 확인했다. Gemini는 전달받은 메뉴 코드와 이 계획을 읽고 독립 카테고리 위치, 상세 화면에서 메뉴 펼침, 목록과 본문의 연결, 공개 전 초안 분리를 검토했다. Gemini가 프로젝트 파일이나 실제 화면을 직접 확인한 것은 아니다. 기획 단계에서는 앱 코드 변경·테스트·빌드·배포를 수행하지 않았다.

후속 답변을 반영할 때 Gemini에게 그림·조작 예제의 배치, 주제별 사례, 접근성 조건에 대한 기획 자문을 받았다. 전달된 요구를 바탕으로 한 자문이며 실제 화면 구현이나 실행 확인은 아니다.

## Explore 메뉴 구현 현황

- Claude가 `app/nav.ts`의 상단·왼쪽 공통 메뉴 자료에 Explore를 추가하고 `app/explore/page.tsx`에 문서 0개의 빈 목록 화면을 구현했다. 기존 자료를 사용하는 모바일 메뉴에도 연결된다.
- `package.json`과 잠금 파일의 제품 버전은 0.9.4다. 팀장이 `npm run build`를 실행했고 `/explore` 정적 페이지 생성까지 성공했다.
- 테스트와 실제 브라우저 클릭·화면 배치 확인은 수행하지 않았다.
- 작업 전 운영 `/explore`는 HTTP 404였다. 공개 GitHub API에서도 해당 저장소를 인증 없이 조회할 수 없었다(HTTP 404; 저장소가 없다는 의미로 단정하지 않음).
- 공유 GitHub 연결·호스트 SSH 키·환경 변수 토큰은 사용하지 않는다. 현재 도구에 프로젝트 전용 GitHub 연결을 통한 게시 경로가 없어 푸시·운영 배포는 대기 상태다. 로컬 변경과 빌드 성공을 운영 반영으로 보고하지 않는다.
