# 온톨로지: 데이터의 의미와 관계를 정하는 지식 설계도

확인일: 2026-10-04 (KST)

## 1. 질문과 핵심 답변

온톨로지는 무엇이고 AI·데이터 작업에서 왜 쓰이나요?

온톨로지는 특정 분야의 개념과 관계, 그 의미와 조건을 명확히 정한 지식 모형입니다. 사람과 시스템이 같은 용어를 같은 뜻으로 이해하도록 돕는 설계도라고 생각하면 쉽습니다.

철학에서는 존재론이라는 뜻으로 쓰지만, 여기서는 AI·정보공학에서 사용하는 의미를 설명합니다. 최근 생성형 AI의 유행 이전부터 지식 표현과 데이터 통합에 쓰여 왔습니다.

## 2. 쉬운 설명

가상의 도서관을 떠올려 보세요. 사서와 로봇 보조원이 '책', '전자책', '저자', '빌림' 같은 말의 뜻과 관계를 미리 합의해 둡니다.

예를 들어 '전자책'은 책의 한 종류(클래스 관계)이고, '전자책 A'라는 특정 자료(개체)가 있고, 민지라는 사람이 그 전자책 A를 빌렸다(관계)는 사실이 있습니다. 전자책 A의 제목이 '별빛 여행'이라는 것은 속성값입니다.

이렇게 뜻과 관계를 먼저 정해 두면, 도서관 시스템도 사람도 같은 기준으로 자료를 찾고 연결할 수 있습니다. 온톨로지는 바로 이 '뜻과 관계를 정하는 설계도' 역할을 합니다.

### 용어 풀이: 클래스·개체·관계·속성·공리

클래스(class)는 책·전자책처럼 같은 종류를 묶은 범주입니다. 개체(individual)는 전자책 A처럼 그 범주에 속하는 특정 대상입니다.

개체끼리 연결하는 관계는 OWL에서 객체 속성으로 표현합니다. 예를 들어 '민지—빌림→전자책 A'에서 빌림이 관계입니다.

개체에 문자·숫자 값을 연결하는 것은 데이터 속성으로 표현합니다. '전자책 A—제목→별빛 여행'에서 제목은 속성이고, 별빛 여행은 그 속성의 값입니다.

공리(axiom)는 이 모형에서 참으로 두는 명제입니다. '전자책은 책의 한 종류'와 'A는 전자책'이라는 두 전제로부터 'A도 책'이라는 결론을 얻을 수 있습니다.

온톨로지가 '의미의 설계도'라면 지식그래프는 그 설계도에 실제 데이터를 채운 지식 지도에 가깝다는 비유로 이해할 수 있습니다. 다만 스키마도 의미·관계를 담을 수 있고 지식그래프에 온톨로지 자체가 포함될 수도 있어, 이 구분은 역할을 보여주는 비유이지 엄격한 분류는 아닙니다.

분류체계(SKOS)의 상하위 관계(broader)는 온톨로지의 클래스 하위 관계(subClassOf)와 같은 것으로 보지 않습니다. 목적에 맞게 필요한 개념을 함께 쓰는 것이 자연스럽습니다.

## 5. 자세한 설명

RDF는 주어—관계(술어)—대상 또는 값 형태로 자료를 표현하는 일반적인 데이터 모델입니다('민지—빌림→전자책 A', '전자책 A—제목→별빛 여행'). 온톨로지만을 위한 것이 아니라 다양한 자료를 표현하는 데 두루 쓰입니다.

OWL은 클래스·관계·공리 등을 표현하는 온톨로지 언어입니다. RDF와 OWL 모두 온톨로지라는 개념 자체가 아니라 그것을 표현하는 W3C 표준이며, 모든 온톨로지에 OWL이 반드시 필요한 것은 아닙니다.

'전자책은 책의 하위 클래스이고 A는 전자책이다'에서 'A는 책이다'를 끌어내는 추론은 OWL만의 기능이 아니라 RDFS로도 할 수 있습니다. 이런 추론에는 이를 지원하는 추론 처리기가 있어야 하며, 자료를 저장만 해 둔다고 자동으로 일어나지는 않습니다.

OWL은 '열린 세계 가정'을 둡니다. 전자책 A에 저자 기록이 없다고 해서 '저자가 없다'거나 데이터가 잘못됐다고 단정할 수 없고, 이 모형의 현재 정보로는 '모른다'고 보는 것입니다.

'모든 책은 저자가 있다'는 공리도 데이터 입력에 저자가 빠졌는지 검사하는 기능과는 다릅니다. 누락된 값을 검출하려면 SHACL처럼 '이 클래스의 자료는 저자 값이 최소 1개 있어야 한다' 같은 제약을 따로 지정해야 합니다. 다만 모든 온톨로지나 데이터베이스가 열린 세계 가정을 쓰는 것은 아니므로 일반화하면 안 됩니다.

SKOS는 분류표나 용어집처럼 상위·하위·연관 개념을 표현하는 데 쓰입니다. 이때의 상하위 관계(broader)는 OWL·RDFS의 클래스 하위 관계(subClassOf)와 같은 것으로 보지 않습니다.

온톨로지·분류체계·데이터베이스 스키마·지식 그래프는 역할이 겹칠 수 있습니다. 설계도와 지도라는 비유도 이해를 돕기 위한 구분입니다. 스키마도 의미와 관계를 담을 수 있고, 지식그래프 안에 온톨로지 자체가 포함될 수도 있으며, 지식그래프를 만드는 데 OWL이 꼭 필요하지도 않습니다.

팔란티어 Foundry의 'Ontology'는 통합한 데이터를 현실의 대상·속성·관계로 연결하고, 실행할 행동·함수·보안 설정까지 함께 다루는 업무용 제품 계층입니다. 이는 일반적인 온톨로지 개념보다 더 구체적인 제품 구현 범위를 가리키는 말이라, 모든 온톨로지가 행동 실행이나 권한 관리까지 자동으로 제공한다고 보면 안 됩니다.

Stanford의 Ontology101(Noy·McGuinness)은 유일하게 옳은 온톨로지는 없다고 설명합니다. 세상 전체를 모델링하기보다 답하고 싶은 질문을 정하고, 범위와 기존 용어를 확인한 뒤 개념·관계를 정의하고 샘플로 검증하며 계속 갱신하는 절차를 권합니다.

목적은 사람과 시스템이 같은 개념을 공통으로 이해하고, 지식을 재사용·통합하고, 숨은 가정을 명시적으로 드러내는 데 있습니다.

문서에 '저자', '주제', '관련 기술' 같은 의미를 온톨로지로 합의해 두면, 검색이나 질문답변 시스템이 관련 정보를 더 정확히 연결하는 데 도움이 됩니다. 다만 이를 LLM과 연결하려면 조회·매핑을 구현해야 합니다.

온톨로지를 만들었다고 모델이 자동으로 학습되거나 환각이 사라지는 것은 아닙니다. 온톨로지를 그려 두는 것만으로 앱 개발이 끝나는 것도 아니며, 입력 데이터와 모형, 원문 검증이 함께 필요합니다.

## 6. 헷갈리기 쉬운 점

- 철학에서 쓰는 '존재론'으로서의 온톨로지와, AI·정보공학에서 특정 분야의 개념·관계를 정의하는 온톨로지는 이름은 같지만 쓰이는 맥락이 다릅니다.

- 속성과 속성값은 다릅니다. '전자책 A의 제목은 별빛 여행'에서 제목은 속성이고, 별빛 여행은 값입니다. 개체 사이의 관계도 OWL에서는 속성으로 표현합니다.

- '전자책은 책의 하위 클래스이고 A는 전자책이다'에서 'A는 책이다'를 끌어내는 추론은 OWL만의 특수 기능이 아니라 RDFS로도 가능하며, 추론 처리기가 있어야 작동합니다.

- 저자 기록이 없다고 해서 '저자가 없다'거나 데이터 오류라고 단정할 수 없습니다. OWL의 열린 세계 가정에서는 이 모형의 현재 정보로 '모른다'고 볼 뿐이며, 모든 온톨로지·데이터베이스가 이 가정을 쓰는 것은 아닙니다.

- RDF·OWL은 온톨로지 개념 자체가 아니라 온톨로지를 표현하기 위한 표준이며, 모든 온톨로지에 OWL이 필수는 아닙니다.

- 팔란티어 Foundry의 'Ontology'는 action·function·보안까지 포함한 구체적인 제품 계층이며, 모든 온톨로지가 행동 실행이나 권한 관리를 자동으로 제공한다는 뜻은 아닙니다.

- 온톨로지를 만들었다고 AI 모델이 자동으로 학습되거나 환각이 사라지는 것은 아닙니다. LLM과 연결하려면 조회·매핑 구현이 따로 필요합니다.

- 이 문서의 그림은 이해를 돕기 위한 가상 도서관 사례이며, 실제 제품 화면이나 실제 실행 결과가 아닙니다.

### 문제 1. 서로 다른 도서관들이 '책·전자책·저자'라는 말의 뜻과 관계를 똑같이 이해하도록 미리 합의하는 작업은 무엇인가요?

1. 서버의 자료를 백업하는 작업
2. 화면의 글꼴과 배치를 조정하는 작업
3. 온톨로지를 설계하는 작업
4. 하루 대출 건수를 집계하는 작업

정답: 3번

해설: 개념·관계·조건을 명확히 정의해 서로 다른 시스템이 같은 뜻으로 이해하게 만드는 작업이 온톨로지 설계입니다. 백업·화면 배치·집계는 이와 다른 실제 운영 업무입니다.

### 문제 2. '전자책'은 하나의 범주(클래스)이고, '전자책 A'는 그 범주에 속한 특정 자료입니다. '전자책 A'는 무엇이라고 부르나요?

1. 클래스
2. 개체
3. 관계
4. 속성값(제목)

정답: 2번

해설: 클래스는 범주(전자책)이고, 그 범주에 속하는 특정 대상이 개체입니다. '전자책 A'는 개체이며, 관계나 속성값과는 다른 용어입니다.

### 문제 3. '모든 전자책은 책이다'라는 공리와 '전자책 A는 전자책이다'라는 정보만 주어졌습니다. 이 둘로 확실히 추론할 수 있는 문장은 무엇인가요?

1. 전자책 A는 책이다
2. 모든 책은 전자책이다
3. 전자책 A의 저자는 민지다
4. 전자책 A는 지금 대출 가능하다

정답: 1번

해설: 전자책이 책의 하위 클래스이고 A가 전자책이라는 조건만으로는 'A는 책이다'만 확실히 추론됩니다. 저자나 대출 가능 여부에 대한 정보는 주어지지 않았습니다.

### 문제 4. OWL 모형에 전자책 A의 저자 정보가 없고, 다른 추론 근거도 없습니다. 이 상태에서 내릴 수 있는 결론은 무엇인가요?

1. 모형에 등록된 모든 사람이 저자다
2. 전자책 A에는 저자가 존재하지 않는다
3. 자동으로 데이터 오류로 처리된다
4. 이 모형의 현재 정보만으로는 저자를 모른다

정답: 4번

### 문제 5. 온톨로지와 지식그래프를 함께 쓰는 예로 옳은 것은 무엇인가요?

1. 그래프를 쓰면 관계나 개념의 의미를 따로 정의할 필요가 없다
2. 온톨로지가 있으면 그래프에 담긴 원본 자료의 사실 여부가 자동으로 보장된다
3. 온톨로지로 '빌림' 관계의 뜻을 정하고, 그래프에 민지가 전자책 A를 빌렸다는 실제 사실을 연결한다
4. 온톨로지와 지식그래프는 항상 같은 뜻으로 쓰이는 말이다

정답: 3번

해설: 온톨로지는 '빌림' 같은 관계와 개념의 뜻을 정의하고, 지식그래프는 그 의미를 바탕으로 실제 대상과 사실을 연결합니다. 온톨로지가 사실 검증을 자동 보장하지 않고, 두 용어가 항상 같은 뜻도 아닙니다.
