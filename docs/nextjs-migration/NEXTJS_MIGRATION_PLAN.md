# AgentTutor Next.js 전환 계획

## 1. 목표

현재 단일 `index.html`로 제공하는 AgentTutor 명령어 문서를 Next.js 기반 웹사이트로 전환한다.

- 문서별 고유 주소 제공
- 전체 문서를 소개하는 홈 화면 추가
- AgentTutor 브랜드를 반영한 문서 디자인 재구성
- 기존 명령어와 출처 정보 보존
- 매일 실행되는 공식 문서 자동 갱신 기능 유지
- GitHub push 후 Vercel 자동 배포 유지

## 2. 확정 사항

| 항목 | 결정 |
| --- | --- |
| 첫 화면 | 전체 문서를 소개하는 홈 화면 |
| 문서 주소 | 문서마다 별도 주소 제공 |
| 색상 모드 | 밝은 화면 중심 |
| 디자인 방향 | 정돈된 기술 문서 |
| 프레임워크 | Next.js App Router |
| 개발 언어 | TypeScript |
| 패키지 관리 | npm |
| 스타일 | 별도 UI 라이브러리 없이 CSS 사용 |
| 자동 갱신 범위 | 신규·삭제 명령 관리 유지 |
| 배포 | GitHub `master` push 후 Vercel 자동 배포 |

## 3. 문서 주소

```text
/
/docs/hanstree
/docs/codex
/docs/claude
/docs/gemini
/docs/antigravity
/docs/grok
```

- `/`는 전체 문서와 주요 기능을 소개한다.
- 각 문서는 고유 주소를 사용한다.
- 새로고침하거나 주소를 공유해도 선택한 문서가 유지된다.

## 4. 권장 프로젝트 구조

```text
AgentTutor/
├─ app/
│  ├─ layout.tsx
│  ├─ page.tsx
│  ├─ globals.css
│  └─ docs/
│     └─ [slug]/
│        └─ page.tsx
├─ components/
│  ├─ AppHeader.tsx
│  ├─ DocSidebar.tsx
│  └─ DocContent.tsx
├─ data/
│  └─ docs.json
├─ scripts/
│  └─ update_docs.py
├─ .github/workflows/
│  └─ update-docs.yml
├─ package.json
├─ package-lock.json
└─ tsconfig.json
```

필요한 파일만 만들며, 한 번만 사용되는 컴포넌트나 불필요한 상태 관리 도구는 추가하지 않는다.

## 5. 데이터 구조 전환

현재 `index.html`에 섞여 있는 목록·출처·본문·명령어를 `data/docs.json`으로 옮긴다.

문서별 기본 데이터는 다음 정보를 포함한다.

```text
id
slug
제목
목록 설명
요약
출처명
출처 URL
갱신 날짜
본문 섹션
명령어
명령어 설명
자동 감지 상태
```

화면은 이 데이터를 읽어 문서 목록과 상세 내용을 렌더링한다.

## 6. 디자인 방향

GitBook 계열의 읽기 쉬운 문서 구조를 바탕으로 AgentTutor 브랜드를 적용한다.

- 밝은 배경과 높은 가독성
- 왼쪽 문서 목록과 오른쪽 상세 내용
- 현재 선택 문서를 명확하게 표시
- 출처와 갱신 날짜를 상세 상단에 표시
- 명령어와 설명을 빠르게 구분할 수 있는 표와 코드 스타일
- 모바일에서는 문서 목록을 접을 수 있는 구조
- 키보드 탐색, 명확한 포커스 표시 등 기본 접근성 반영
- 불필요한 애니메이션과 장식 배제

## 7. 화면 구성

### 홈 화면

- AgentTutor 소개
- 제공 문서 목록
- 각 문서의 간단한 설명과 바로가기
- 자동 갱신 기준과 최근 갱신 정보

### 문서 상세 화면

- 문서 제목
- 공식 출처 링크
- 갱신 날짜
- 명령어 분류와 설명
- 신규 감지 명령
- 공식 문서에서 확인되지 않는 명령 상태
- 다른 문서로 이동하는 공통 목록

## 8. 자동 갱신 이전

현재 자동 갱신 스크립트는 `index.html` 문자열을 직접 수정한다. Next.js 전환 후에는 `data/docs.json`만 변경하게 한다.

```text
공식 문서 수집
  → 이전 스냅샷과 비교
  → 신규·삭제 명령 판정
  → data/docs.json 갱신
  → master 자동 커밋
  → Vercel 자동 빌드·배포
```

유지할 정책:

- 매일 오전 6시 KST 실행
- Codex, Claude, Gemini, Antigravity, Grok만 자동 확인
- Hanstree 문서는 자동 갱신에서 제외
- 신규 명령은 자동 관리 영역에 추가
- 사라진 명령은 삭제하지 않고 `공식 문서에서 확인되지 않음`으로 표시
- 한 출처라도 수집·분석에 실패하면 기존 정상 데이터 보존
- 변경이 없으면 파일과 커밋을 만들지 않음
- 실패 시 같은 제목의 열린 GitHub Issue가 없을 때만 Issue 생성

## 9. 구현 순서

1. Next.js App Router와 TypeScript 기본 환경 구성
2. 현재 문서 내용을 구조화된 데이터로 이전
3. 공통 레이아웃과 문서별 동적 경로 구현
4. 홈 화면 구현
5. 새 디자인과 반응형 화면 적용
6. 출처 링크와 갱신 날짜 연결
7. 자동 갱신 스크립트를 `data/docs.json` 기준으로 변경
8. GitHub Actions의 변경 파일과 실행 명령 수정
9. 기존 문서 내용 누락 여부 확인
10. Next.js 빌드 확인
11. GitHub push 및 Vercel 배포 확인
12. 운영 화면 확인 후 기존 `index.html` 삭제

## 10. 완료 기준

- `/` 홈 화면이 정상 표시된다.
- 문서 6개가 각각 고유 주소에서 열린다.
- 기존 명령어, 설명, 출처가 누락되지 않는다.
- Gemini와 Antigravity 내용이 서로 섞이지 않는다.
- 데스크톱과 모바일에서 문서를 읽고 이동할 수 있다.
- 공식 출처 링크가 새 탭에서 열린다.
- 자동 갱신 스크립트가 현재 공식 문서를 정상 수집한다.
- 변경이 없을 때 파일을 수정하지 않는다.
- GitHub Actions 예약 실행 설정이 유지된다.
- Next.js 빌드가 완료된다.
- Vercel 운영 주소에 새 화면이 반영된다.

## 11. 전환 안전 원칙

- Next.js 화면과 데이터 이전을 확인하기 전에는 기존 `index.html`을 삭제하지 않는다.
- 기존 문서 내용을 임의로 축약하거나 재해석하지 않는다.
- 새 의존성과 구조는 실제 필요한 범위로 제한한다.
- 자동 갱신 실패 시 마지막 정상 데이터를 계속 제공한다.
- 운영 배포 확인 후에만 전환 완료로 판단한다.
