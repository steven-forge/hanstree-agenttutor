# AgentTutor 카드뉴스 관리

관리자 화면 경로: `/admin/news`. 메뉴와 직접 주소 접근 모두 비밀번호를 먼저 확인한다. `/admin/news?mode=server`도 같은 인증을 거친다.

## 현재 사용 방식

2026-10-06 사용자 지시로 **카드 10장 자동 제작과 Instagram 예약 발행**을 추가했다. 기본 예약 시각은 제작 08:05·발행 09:00 KST이며 관리 화면에서 변경한다. 정기 예약은 관리자가 켜서 저장해야 작동한다. 기존의 관리자 검토 후 발행 버튼도 유지한다. 인스타그램 계정 연결은 새 `/admin/news/instagram` 연결 관리 화면에서 진행한다(절차는 `docs/today/INSTAGRAM_CONNECTION.md`). 연결하지 않아도 아래 원고 작업은 그대로 할 수 있다.

관리자 비밀번호로 로그인한 뒤에는 Instagram 연결 전에도 브라우저 작업 공간에서 후보 수집, 10개 선정, 카드 원고·순서 수정, 출처 확인, 설명 작성, JPG 10장 ZIP 다운로드가 가능하다. 초안은 **이 브라우저의 localStorage**에 저장된다. 기기·브라우저 간 동기화는 없으며 브라우저 데이터 삭제 시 지워진다. JSON 내보내기 또는 ZIP 안의 `draft.json`으로 백업한다. JSON 가져오기는 해당 날짜의 초안으로 복원하며 확인 체크와 승인을 다시 받아야 한다.

1. 관리자 비밀번호로 로그인한 뒤 날짜를 고르고 **뉴스레터 불러오기** 또는 **뉴스 직접 등록**으로 시작한다.
2. 후보 중 중요도 순으로 서로 다른 뉴스 10개를 고른다. 같은 사건을 다룬 기사 여러 개를 별도 뉴스로 세지 않는다.
3. 원문을 읽고 한국어 제목·본문을 다듬는다. 초안은 카드 전용 짧은 원고 또는 규격에 맞는 기존 편집 요약을 사용한다. 기사 내용의 최종 검증은 관리자가 한다.
4. 기사별 실제 발행 시각과 수치·조건을 확인하고 확인 체크를 한다.
5. 뉴스 선택 시 자동 입력되는 소개 문구와 뉴스 제목 목록을 확인하고 **원고 저장 → 실제 저장본 JPG 보기 → 10개 원고 검토 완료** 순으로 진행한다.
6. **JPG 10장 ZIP 받기**로 이미지·캡션·원문 목록을 받는다. 계정 연결 후에는 연결 계정 이름을 확인하고 발행 버튼으로 실제 게시한다.

### Explore 웹툰 발행 — v0.14.7

- 왼쪽 메뉴 **카드뉴스 관리 → Explore 웹툰 발행**(`/admin/news/explore`)에서 문서를 고르고 **선택한 문서의 웹툰 불러오기**를 누른다. 이미 만들어진 설명 웹툰을 사용하며, 비교 웹툰이 있으면 함께 선택할 수 있다.
- 원본 전체를 자르지 않고 흰 여백의 **1080×1350 JPG**로 변환한다. 긴 웹툰은 글씨가 작아질 수 있으므로 실제 저장본 JPG를 확인한다. 한 장은 단일 이미지, 두 장은 넘겨 보는 게시물로 발행한다. 그림·말풍선은 이 화면에서 편집하지 않는다.
- **웹툰 선택·순서 조정 → 실제 JPG 확인 → 확인 체크 → 원고 저장 → 검토 완료 → Instagram에 발행** 순서다. 게시글 설명은 문서 소개·원문 링크로 시작하며 직접 수정할 수 있다. 초안 생성·저장·검토만으로 게시하지 않는다.
- 기존 Explore 텍스트 카드 생성·편집은 종료한다. 관리자 웹툰 화면에 진입하면 이전 미발행 텍스트 초안과 승인 원고를 서버에서 삭제한다. 이미 발행했거나 발행을 시도한 기록은 중복 게시 방지를 위해 이력으로 남기며 편집하지 않는다. 일일 뉴스 원고에는 적용하지 않는다.
- 서버 저장소가 필요하다. 웹툰은 날짜·문서별 `YYYY-MM-DD~webtoon~slug`로 저장하며 일일 뉴스와 분리한다. 재선택하면 기존 웹툰 원고를 연다. 원본이 변경되면 기존 승인으로 발행하지 않으며 다른 판본 날짜에서 다시 불러와 검토한다.
- 계정별 최근 게시 후 **1시간 제한**과 결과 미확정 시 중복 발행 차단을 뉴스와 함께 적용한다. 수동 웹툰 발행은 일일 뉴스 자동 예약과 별도다. 기존 `/admin/news?explore=문서번호` 주소는 새 페이지로 연결한다.

2026-10-07 확인: 빌드·TypeScript와 격리 점검 39개 통과. 등록 문서 17개·원본 18개를 실제 1080×1350/sRGB JPG로 변환했고, 1장과 2장 발행 분기·1시간 제한·중복 발행 차단·원본 변경 거절을 확인했다. 로컬 관리자 브라우저에서 텍스트 초안 자동 삭제, 뉴스·발행 이력 보존, 웹툰 선택·이동·저장·검토·ZIP, 1440/390px 가로 넘침 없음과 브라우저 오류 없음을 확인했다. 운영 비밀번호·Redis·Instagram 계정은 사용하지 않았으며 실제 게시 요청은 보내지 않았다.

### Instagram 발행 진행 확인

발행 요청을 시작하면 **Instagram 발행 진행** 영역으로 이동한다. **카드 준비 → 게시물 구성 → 이미지 처리 → 최종 발행** 단계를 표시하고, 준비 요청을 마친 카드 수(`3/10장` 등), 최근 처리 내용, 발행 시작·마지막 처리·조회 시각을 보여 준다. 이 수치는 이미지 준비 요청 수이며 Instagram 처리의 완료율을 추정한 백분율이 아니다. 기존 기록에 시작 시각이 없으면 ‘기록 없음’으로 표시한다. 판본 이력에서도 현재 판본의 진행 요약과 상세 이동 링크를 볼 수 있다.

- 화면이 보이는 동안 서버에 저장된 진행 기록을 10초마다 읽는다. Instagram의 원격 처리 상태는 마지막 처리 후 1분이 지난 작업에서 1분 간격으로 최대 5회 조회한다. 완료 기록이 저장되거나 로그인 세션이 만료되면 자동 확인을 멈춘다.
- 자동 조회는 읽기 전용이다. 원고·판본 상태를 변경하거나 발행을 재시도하지 않는다. 원격 조회 실패 시 마지막 정상 기록을 유지하고 오류를 표시한다.
- `이미지 처리 완료`는 아직 공개 게시 완료가 아니다. **발행 계속 및 확인**을 누르면 최초 요청한 게시물의 발행을 이어간다. 이미 최종 발행 요청을 보낸 작업은 결과만 확인하며 같은 요청을 다시 보내지 않는다.
- Instagram에서 게시 완료가 확인됐지만 판본 기록이 아직 이전 상태라면 **완료 기록 확인**을 눌러 완료 상태를 저장한다. 게시물 링크가 확보된 경우 바로 열 수 있다.
- 기존 복구 대기 시간도 표시한다. 컨테이너가 있으면 마지막 처리 후 1분, 카드 준비 중 요청이 끊겨 컨테이너가 없으면 마지막 처리 후 10분이 지나야 이어서 확인할 수 있다. 오래 변화가 없다는 이유만으로 성공·실패를 확정하지 않는다.
- 새 조회 경로는 관리자 인증이 필요한 `/api/admin/news/progress`이며 비공개·캐시 금지를 적용한다. 다른 계정으로 연결된 작업을 조회하거나 자동으로 이어 발행하지 않는다. 실제 판본 상태 변경은 기존 명시적 발행·확인 경로와 저장 버전 검사를 따른다.

## 시간과 수집 기준

- 후보는 `/today` 뉴스레터 공개 기사와 관리자가 직접 등록한 뉴스를 사용한다. 뉴스레터는 같은 데이터와 릴리스 제외 기준을 사용한다. 직접 등록은 카드뉴스 후보에만 추가하며 공개 뉴스레터에 게시하지 않는다. 원문 URL의 내용은 관리자가 **한국어 제목·요약 가져오기**를 눌렀을 때만 읽는다.
- 후보 기간은 뉴스레터 전체를 기본으로 한다. 판본일 이후와 미래 기사는 제외하고 최신순으로 보여 준다. 판본 날짜는 카드 게시일이며 개별 기사 발행일을 오늘로 바꾸지 않는다. 08:30 검토 준비, 09:00 발행은 운영 목표다.
- 후보별 뉴스레터 상세 링크와 원문·실제 발행일을 표시한다. 제목과 요약은 뉴스레터의 편집본을 먼저 사용한다. 원문 URL 중복을 제거하며 중요도와 같은 사건 여부는 관리자가 판단한다.
- 날짜만 제공되는 기사는 정확한 시각 확인 전까지 검토 완료할 수 없다. 미래 시각, 판본 범위 밖 기사, 중복 URL·제목, 확인하지 않은 카드, 10개 미만·초과, 긴 줄, 2,200자 초과 캡션은 승인할 수 없다.
- 후보가 10개 미만이면 오류로 표시한다. 뉴스레터에 기사와 수집 상태를 먼저 확인한다. 직접 등록한 뉴스도 후보 수에 포함하며, 과거 RSS 보관용 후보는 제외한다.
- 기존 초안을 갱신하면 카드의 편집 내용·순서·캡션을 보존한다. 직접 등록한 후보와 입력 원문은 계속 유지한다. 뉴스레터에서 사라진 기존 선택은 백업용으로 남지만 새 후보 수에서 제외하고 새 승인 전 다시 선정하도록 안내한다. 승인·발행 중인 원고는 자동 변경하지 않는다.
- JSON 복원 시에도 뉴스레터 후보를 다시 불러와 연결하고 확인 체크·승인을 해제한다. 기사 목록 갱신은 뉴스레터 데이터가 운영 배포된 뒤 반영되며, 카드 후보 API는 관리자 인증과 비공개·캐시 금지를 유지한다.

## 뉴스 직접 등록

화면 상단의 **뉴스 직접 등록**을 펼쳐 원문 HTTPS 주소를 넣고 **한국어 제목·요약 가져오기**를 누르면 한국어 제목과 본문 요약이 입력된다. 내용을 검토·수정하고 출처 이름과 실제 발행 시각(KST)을 확인한 뒤 **뉴스 등록**을 누른다. 모든 항목을 직접 입력할 수도 있으며, 해당 날짜의 판본이 없어도 시작할 수 있다.

- 등록 즉시 후보와 작성 중인 카드 원고·설명을 함께 저장한다. 후보에 **직접 등록** 표시가 붙으며, 체크해야 카드로 선정된다.
- 뉴스레터 다시 불러오기, 페이지 새로고침, 원고 JSON 내보내기·가져오기에서도 수동 후보를 보존한다. 저장 위치는 현재 브라우저/서버 모드를 따른다.
- 같은 원문 URL(추적 매개변수·끝 슬래시·주소의 # 부분 제외)은 중복 등록할 수 없다. 미래 또는 판본 날짜 이후의 발행 시각, 누락된 필수 항목, HTTPS가 아닌 주소는 등록하지 않는다.
- 긴 입력을 임의로 자르거나 말줄임표로 바꾸지 않는다. 카드 규격에 맞으면 원고에 자동 입력하며, 맞지 않으면 카드 편집에서 제목 2줄·본문 7줄 이내로 직접 정리한다.
- 등록은 공개 게시가 아니다. 출처 검토·10개 선정·원고 승인·발행 버튼의 기존 절차를 그대로 따른다. 검토 완료된 판본에 등록하면 초안으로 돌아가 다시 검토해야 한다. 발행이 시작된 판본은 변경할 수 없다.

### URL에서 제목·본문 가져오기

- 공개 HTTPS HTML 기사의 제목은 한국어로 번역하고, 본문은 전체에서 핵심 문장을 골라 요약한 뒤 한국어로 번역한다. 이미 한국어인 기사는 번역 없이 요약한다. 결과를 자동 등록·게시하지 않는다. 사이트에서 확인되는 출처와 정확한 발행 시각도 채우며, 시간대가 없거나 날짜만 있으면 발행 시각은 직접 확인해 입력한다.
- 작성 중인 제목·내용·출처·시각이 있으면 교체 확인을 받는다. 가져오기에 실패하면 기존 입력을 그대로 유지한다.
- 요약은 완결된 문장을 사용하며 문장 중간을 자르거나 말줄임표를 붙이지 않는다. 제목 200자·내용 600자 이내로 정리할 수 없으면 오류로 안내한다. 출처는 100자 이내로 직접 정리해야 할 수 있다. 최대 50,000자보다 긴 원문은 오류로 안내한다. 카드 선정 후 제목 2줄·본문 7줄 검사는 별도로 유지한다.
- 번역에는 뉴스레터 수집에서 사용 중인 MyMemory 공개 번역 API를 사용한다. 공개 원문 제목과 요약으로 선정된 문장만 전달하며 관리자 입력·비밀번호·쿠키를 전달하지 않는다. 서비스 제한·번역 실패·언어 판별 실패 시 영문을 성공 결과로 대신 입력하지 않는다. 자동 번역의 수치·조건과 문맥은 등록 전에 원문과 대조한다.
- 로그인이 필요한 기사, 유료 벽, 자동 접근을 차단한 사이트, JavaScript 실행 후 본문을 만드는 페이지, PDF 등은 가져오지 못할 수 있다. 원문을 직접 확인해 입력한다.
- 기존 관리자 로그인과 동일 출처 검사를 적용하며 서버 저장소 연결 없이도 사용할 수 있다. URL은 공개 도메인의 HTTPS 443만 허용한다. 내부·특수 IP와 IP 직접 주소를 차단하고, DNS 결과 확인 후 연결 IP를 고정한다. 이동 주소도 매번 검사하며 최대 3회 이동·전체 20초·압축 전후 각각 2MiB·HTML만 허용한다. 쿠키·인증 정보를 원문 사이트에 전달하지 않는다.

### 뉴스레터 설정 저장소 연결

| 환경변수 이름 | 용도 |

| `NEWSLETTER_REDIS_REST_TOKEN` | 위 저장소의 REST 접근 권한 |

설정 저장소가 없으면 저장 버튼을 잠그고 연결 안내를 표시한다. 저장소 설정 유무와 실연결 성공은 구분한다. 현재 정책과 최근 이전 버전 최대 20개를 서버에 보관하며 UI에서 과거 버전을 복원하는 기능은 없다. 공개 `/api/news-policy`는 비밀 없는 검증된 수집 기준만 제공하고 수정은 관리자 인증·동일 출처 확인이 필요한 `/api/admin/news-policy`에서만 가능하다.

## 저장과 발행 보호

- 관리 페이지와 후보·관리자 API는 서버에서 인증을 확인한다. 수정 요청은 출처도 확인한다. 세션은 8시간 만료, HttpOnly·SameSite=Strict, 운영 HTTPS에서 Secure 쿠키를 사용한다.
- 저장소 연결 전에는 비밀번호와 독립된 비밀값으로 서명한 쿠키를 사용한다. 로그인 시도 제한은 서버 인스턴스마다 15분 20회로, 여러 인스턴스 전체의 제한을 보장하지 않는다. Redis 연결 후에는 중앙 시도 제한과 서버 저장 세션을 사용한다. 로그인·로그아웃 모두 비밀번호 값을 기록하지 않는다.
- 저장은 버전 비교와 이력 갱신을 함께 처리한다. 다른 탭에서 먼저 수정했으면 덮어쓰지 않는다.
- 승인 뒤 수정하면 다시 초안으로 돌아간다. 발행이 시작된 원고는 잠근다.
- JPG는 서버 비밀값으로 서명한 24시간 임시 URL로만 Meta에 전달한다. 원고 JSON·토큰·관리자 쿠키는 공개하지 않는다.
- 발행 요청 전에 기록을 저장한다. 응답이 불명확하면 ‘발행 결과 확인 필요’로 남기며 같은 최종 요청을 자동 재전송하지 않는다. ‘발행 계속 및 확인’은 이미지 준비가 끝났고 최종 발행 요청 전인 경우 원래 요청을 이어서 게시한다.
- 인스타그램에서 완료 응답을 받거나 실제 컨테이너의 `PUBLISHED` 상태를 확인했을 때만 ‘발행 완료’로 표시한다.

사용자가 운영 비밀번호를 4자리로 등록했다고 알려, 관리자 진입 조건을 4~256자로 변경했다. 비밀번호 값은 읽지 않는다. 기존 비밀번호 대조, 로그인 시도 제한, 세션 만료, 무인증 API 차단은 유지한다.

4자리 비밀번호에서 로그인 시도 제한이 우회되지 않도록, 브라우저 세션에는 비밀번호와 독립된 `CARD_NEWS_SIGNING_SECRET`을 필수로 사용한다. 보호값 없이 비밀번호만으로 세션을 만드는 경로는 열리지 않는다. Redis 모드에서는 서버에 보관된 난수 세션만 허용한다.

사용자가 보호값 등록 완료를 알렸으며 값은 전달받거나 읽지 않았다. v0.12.2 빌드 성공 후 로컬 일회성 4자리 비밀번호로 로그인 성공·실패·로그아웃을 확인했다. 보호값 누락 시 로그인 503, 비밀번호만으로 만든 위조 세션은 보호값 유무와 무관하게 401로 차단되는 것도 확인했다.

## 로그인 설정 안내 — v0.12.3

로그인 입력란이 비활성일 때 필요한 항목을 구체적으로 안내한다. 비밀번호 또는 보호값이 운영 배포에 없는지, 허용 길이 조건에 맞지 않는지만 구분한다. 비밀값과 실제 글자 수는 응답에 포함하지 않는다. 설정은 이 운영 주소를 배포하는 Vercel 프로젝트의 Production 대상이어야 하며 변경 후 재배포해야 한다.
