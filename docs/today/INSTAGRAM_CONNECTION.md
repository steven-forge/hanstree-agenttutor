# Instagram 연결 설정 — Instagram Login (Business Login)

관리자 화면 경로: `/admin/news/instagram`. 카드뉴스 관리 메뉴와 `/admin/news` 본문 링크로 이동한다. 로그인은 기존 카드뉴스 관리자 비밀번호를 그대로 사용한다.

v0.13.6 통합 빌드에 포함했다. 공통 로그인 화면의 **하루 동안 로그인 유지**를 체크하면 같은 브라우저에서 24시간 관리자 인증을 유지한다. Instagram 연결 동의의 일회용 요청은 기존 10분 만료를 유지한다. 로컬에서 관리자 로그인 보호와 연결 미설정 상태의 화면 진입을 확인했으며 실제 Instagram 연결·동의·발행은 수행하지 않았다.

이 문서는 공식 Meta 문서 기준(2026-10-04 확인)의 **Instagram Login(비즈니스 로그인)** 방식만 다룬다. Facebook 로그인 방식은 사용하지 않는다.

- [Instagram API with Instagram Login — Business Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/business-login)
- [콘텐츠 발행 한도 조회(`content_publishing_limit`)](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/content_publishing_limit)

> **확인 상태(빌드 당시 v0.13.3, 2026-10-04 KST)**: 비밀 설정 파일을 제외한 프로젝트 내부 소스 사본에서 운영용 빌드와 타입 검사가 통과했다. 새 관리자 화면·연결 API·콜백이 빌드에 포함됐으며 관련 앱 소스 10개가 빌드 사본과 일치함을 확인했다. 병행 작업에서 패키지 버전이 v0.13.5로 바뀌었으나 두 패키지 파일은 버전 값 외에는 빌드 사본과 같다. 실제 Meta 앱·OAuth 동의·토큰 교환·`/me`·`content_publishing_limit`·실제 발행은 수행하지 않았다. 테스트 러너는 실행하지 않았다.

독립된 Gemini 읽기 전용 소스 검토 보고서에서 진행을 막는 보안 결함은 발견되지 않았다. 연결 해제와 최종 게시 요청 사이의 짧은 경쟁 구간은 아래 알려진 한계에 남겼다. 이는 소스 검토 결과이며 실제 계정 연결 성공을 확인한 결과는 아니다.

## 준비물

1. **Instagram 프로페셔널 계정**(비즈니스 또는 크리에이터). 개인 계정은 연결할 수 없으며, `/me`의 `account_type`이 프로페셔널이 아니면 연결을 저장하지 않는다.
2. Meta 개발자 계정과 **Instagram API가 추가된 Meta 앱**. 앱 설정 화면에서 Instagram Login용 **Instagram App ID와 App Secret**을 사용한다. 일반 Meta 앱 ID를 대신 입력하지 않는다.
3. 개발 단계에서는 연결할 Instagram 계정을 앱의 **역할(Role)** 또는 **테스터**로 등록해야 로그인할 수 있다. 앱 검토(App Review) 통과 전에는 등록된 역할/테스터 계정만 연결할 수 있으며, 실제 검토 통과와 배포 범위 확대는 이 작업의 범위 밖이다.

## 등록할 환경변수 (Vercel Production, 값은 여기에 적지 않음)

| 이름 | 용도 |
| --- | --- |
| `INSTAGRAM_APP_ID` | Instagram Login용 App ID (일반 Facebook App ID 아님) |
| `INSTAGRAM_APP_SECRET` | 위 앱의 App Secret |
| `CARD_NEWS_PUBLIC_URL` | 실제 배포된 HTTPS 주소. 현재 운영 주소는 `https://hanstree-agenttutor-jgwu.vercel.app` |
| `CARD_NEWS_SIGNING_SECRET` | 기존 서명 비밀값, 32자 이상. 저장된 토큰 암호화 키도 여기서 파생한다 |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | 기존 카드뉴스 Redis. OAuth 상태와 연결 정보 저장에 필요하다 |
| `INSTAGRAM_API_VERSION` | 선택. 기본 `v26.0`. 설정한다면 `v숫자.0` 형식이어야 한다 |

위 항목 중 하나라도 빠지거나 형식이 맞지 않으면 **연결** 버튼이 비활성화되고, 연결 시작 요청도 대기 상태를 만들기 전에 거부된다. 화면의 **연결 준비 상태와 설정 도움말**에는 부족한 설정의 **이름만** 표시되며 값은 표시되지 않는다.

### 콜백(redirect) 주소

콜백 주소는 코드에 고정되어 있고 `CARD_NEWS_PUBLIC_URL`을 기준으로 계산된다. 현재 운영 주소 기준으로 Meta 앱의 **유효한 OAuth 리디렉션 URI**에 아래 주소를 그대로 등록한다.

```
https://hanstree-agenttutor-jgwu.vercel.app/api/admin/news/instagram/callback
```

같은 주소가 연결 화면의 설정 도움말에도 복사할 수 있게 표시된다. `CARD_NEWS_PUBLIC_URL`을 바꾸면 이 주소도 함께 바뀌므로 Meta 앱 설정을 다시 맞춰야 한다. 임의의 리디렉션 주소는 허용하지 않는다.

요청하는 권한 범위는 `instagram_business_basic`, `instagram_business_content_publish` 두 가지로 고정했다.

## 화면에서 보는 상태

화면은 네 가지를 따로 표시한다. 앞의 것이 뒤의 것을 보장하지 않는다.

| 항목 | 의미 |
| --- | --- |
| 연결 설정 | 이 서버에 사용할 수 있는 연결 정보가 있는지(저장됨 / 만료됨 / 읽을 수 없음 / 해제됨 / 없음). Redis 기록과 환경변수만 보고 판단하며 Instagram에 물어본 결과가 아니다 |
| 실제 계정 확인 | 마지막으로 **연결 확인**(또는 연결 직후)에 Instagram `/me`가 같은 계정 ID를 돌려줬는지와 그 시각 |
| 발행 권한 확인 | 마지막 **연결 확인**에서 `content_publishing_limit`이 유효한 사용량 값을 돌려줬는지와 그 시각 |
| 카드뉴스 발행 | 카드뉴스 화면의 발행 버튼이 켜지는 조건(공개 HTTPS 주소·서명 비밀값·저장소·만료/해제되지 않은 연결 정보)을 만족하는지 |

‘실제 계정 확인’과 ‘발행 권한 확인’은 **마지막 확인 시점의 기록**이며 실시간 상태가 아니다. 그 뒤에 Instagram 쪽에서 권한이 철회돼도 다시 **연결 확인**을 누르기 전에는 바뀌지 않는다. 실제 발행 직전에는 항상 `/me`를 다시 조회해 계정을 확인한다.

## 화면에서 하는 일

- **Instagram 연결 / 다시 연결**: Instagram 인증 화면으로 이동해 동의한다. 돌아오면 결과만 적힌 간단한 안내 화면이 나오고, 거기서 **관리자 화면으로 돌아가기** 링크를 눌러야 한다(자동 이동 없음). 연결 화면은 주소의 `status=connected`만으로 성공을 표시하지 않고, 저장된 연결 기록이 방금 만들어진 것일 때만 성공으로 표시한다.
- **연결 확인**: 계정 정보(`/me`)와 콘텐츠 게시 한도(`content_publishing_limit`)를 조회한다. 게시물을 만들지 않는다. 계정 확인에 실패하면 실패 시각·사유를 기록하고 이전의 발행 권한 확인 기록을 지운다(저장된 토큰은 지우지 않는다). 계정은 확인됐지만 게시 한도 응답이 비었거나 형식이 맞지 않으면 발행 권한은 ‘확인되지 않음’으로 되돌린다. 확인 도중 다른 작업이 연결 정보를 바꿨다면 결과를 저장하지 않고 그렇게 알린다.
- **연결 갱신**: 연결·갱신 후 24시간이 지나고 만료 전일 때만 가능하다. 자동 갱신은 하지 않으며, 실패해도 기존 토큰은 그대로 유지한다. **만료된 연결은 갱신할 수 없고 다시 연결해야 한다.**
- **이 사이트 연결 해제**: 이 서버에 저장된 연결만 삭제한다. 만료됐거나 읽을 수 없는 연결도 해제할 수 있다. Meta 쪽 권한 자체는 해제되지 않으며, 완전히 철회하려면 Instagram 계정의 앱 권한 설정에서 직접 해제해야 한다.

연결 화면은 계정 연결 상태만 관리한다. 카드 10장 제작·검토와 실제 발행 버튼은 기존 `/admin/news`에서 그대로 진행하며, 이 화면에서 게시하지 않는다.

`CARD_NEWS_SIGNING_SECRET`을 교체하면 이전 값으로 암호화한 토큰은 읽을 수 없게 된다. 이때 화면은 ‘저장된 연결을 읽을 수 없음’으로 표시하고, 다시 연결하거나 해제할 수 있다.

## 기존 고정 토큰 방식(레거시)과의 관계

과거 방식인 `INSTAGRAM_USER_ID`/`INSTAGRAM_ACCESS_TOKEN` 환경변수도 계속 지원한다.

- OAuth로 연결한 기록이 있으면 그 토큰만 사용한다. OAuth 연결이 만료되거나 읽을 수 없게 돼도 고정 토큰으로 조용히 넘어가지 않는다.
- **이 사이트 연결 해제**를 누른 뒤에는 고정 토큰 환경변수가 남아 있어도 사용하지 않는다. 이 상태에서 다시 발행하려면 OAuth로 다시 연결해야 한다(해제 상태를 고정 토큰 방식으로 되돌리는 버튼은 없다).
- 고정 토큰만 설정된 상태는 화면에서 ‘고정 토큰 설정 있음’으로만 표시하며 연결된 것으로 표시하지 않는다. **연결 확인**을 눌러야 실제 계정·발행 권한 확인 기록이 생긴다. 이 기록은 설정된 ID·토큰의 지문(서버 비밀값으로 만든 해시)에 묶여 저장되고, 환경변수 값이 바뀌면 기록을 무시하고 다시 확인하라고 안내한다. 토큰 자체는 저장하지 않는다. 저장소가 없으면 확인 결과는 저장되지 않고 그 화면에만 표시된다.
- 고정 토큰만 있는 상태에서는 이 서버에 저장된 연결이 없으므로 해제 버튼이 비활성화된다. 사용을 멈추려면 환경변수를 직접 삭제한다.
- OAuth와 고정 토큰 모두, 발행 직전과 연결 확인 때 `/me`의 `user_id`가 설정·저장된 계정 ID와 같은지 확인하고 다르면 거부한다.

## 보안 설계 요약 (구현된 내용)

- 관리자 로그인 쿠키는 `SameSite=Strict`를 그대로 유지한다. Instagram에서 돌아오는 콜백에는 Strict 쿠키가 전달되지 않으므로 콜백은 이 쿠키를 요구하지 않는다. 대신 연결 시작 때 만든 10분짜리 `SameSite=Lax` 상태 쿠키와, Redis에 저장한 1회용 기록(로그인 세션 해시·비밀번호 버전·시작 시점의 연결 버전)으로 검증한다. 기록은 한 번 쓰면 삭제된다.
- 콜백의 최종 저장은 Redis에서 한 번에 처리한다: 연결을 시작한 관리자 세션이 아직 유효하고, 연결 정보가 **연결을 시작한 시점의 버전 그대로**일 때만 저장한다. 그 사이에 로그아웃·연결 해제·다른 연결·갱신·연결 확인 기록 저장이 있었다면 저장을 거부하므로 다시 연결해야 한다. 늦게 도착한 콜백이 더 최근의 해제·연결을 덮어쓰지 못한다.
- 콜백 응답은 고정된 안내 문구와 같은 사이트 링크만 담은 화면이다. 인증 코드·토큰·Instagram이 돌려준 오류 문구를 넣지 않으며, 캐시 금지·Referrer 미전송·제한적 CSP를 적용하고 주소창의 코드 값을 지운다.
- 토큰은 `CARD_NEWS_SIGNING_SECRET`에서 파생한 키로 AES-256-GCM 암호화해 Redis에 저장한다. 평문·암호문·지문 모두 브라우저로 보내지 않으며, 화면에는 계정명·권한 범위·시각 등만 전달한다.
- 발행·발행 확인 작업은 시작할 때 연결 정보(토큰과 계정 ID)를 **한 번** 읽어 그 작업의 모든 Instagram 요청에 같은 값을 쓴다. 최종 발행 요청 직전에 연결이 해제·교체·갱신되지 않았는지 다시 확인하고, 바뀌었다면 최종 발행 요청을 보내지 않고 ‘확인 필요’ 상태로 멈춘다. **연결 확인**으로 기록만 바뀐 경우는 진행 중인 발행을 멈추지 않는다.
- 발행 확인(이어서 발행)은 발행을 시작한 계정 ID가 현재 연결과 다르면 거부한다. 계정 기록이 없는 과거 발행 작업은 완료 여부 조회만 하고 이어서 발행하지 않는다.
- 최종 발행 요청 전에 요청 시각을 먼저 저장하며, 결과가 불명확한 최종 발행 요청은 자동으로 다시 보내지 않는다(기존 동작 유지).

## 알려진 한계

- ‘발행 직전 재확인’과 실제 최종 발행 요청 사이에는 짧은 간격이 있다. 그 순간에 연결을 해제하면 이미 읽어 둔 토큰으로 요청이 나갈 수 있다. 다른 계정으로 게시되지는 않는다(계정 ID와 토큰이 함께 고정됨).
- 발행 도중 **연결 갱신**을 하면 연결이 바뀐 것으로 보고 최종 발행 전에 멈춘다. 이 경우 1분 뒤 **발행 계속 및 확인**으로 이어갈 수 있다.
- Instagram에서 진행 중인 OAuth 동의와 **연결 확인**이 겹치면 콜백 저장이 거부될 수 있다. 다시 연결하면 된다.
- 화면의 확인 기록은 마지막 확인 시점 기준이며 자동으로 다시 조회하지 않는다. 자동(무인) 토큰 갱신도 없다.

## 확인하지 않은 부분

- 실제 Meta 앱 생성, OAuth 동의 화면 진행, 토큰 발급·교환, `/me`·`content_publishing_limit` 실제 응답, 실제 발행은 수행하지 않았다. 응답 형식 검증(`/me`의 `user_id`·`username`·`account_type`, 게시 한도의 `data[0].quota_usage`)은 공식 문서의 예시를 기준으로 작성했으며, 실제 응답이 다르면 연결 또는 확인이 실패로 표시될 수 있다.
- 앱 검토(App Review) 통과 여부와 실제 배포 범위는 운영자가 Meta 개발자 콘솔에서 별도로 진행해야 하며, 검토 통과를 보장하지 않는다.
- 운영용 빌드·타입 검사는 통과했다. v0.13.6 `2982c5b` 통합 배포 후 2026-10-04 10:18 KST 운영 `/admin/news/instagram`의 관리자 로그인 화면·로그인 유지 체크박스와 비로그인 연결 API 401을 확인했다. 실제 계정이 연결된 브라우저 동작과 실게시 성공은 아직 확인하지 않았다.
