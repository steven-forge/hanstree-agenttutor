# 뉴스레터 외부 채널 관리

v0.13.4부터 관리자 메뉴 **카드뉴스 관리 → 뉴스레터 기준 설정 → 외부 매체와 참고 채널**에서 관리한다. 기존 관리자 로그인이 필요하다.

- 각 채널의 홈페이지와 RSS·Atom 또는 수집 API 주소를 직접 수정할 수 있다. **주소 열기**로 입력한 주소를 새 탭에서 확인한다. 잘못된 주소는 저장할 수 없다.
- 주소 수정도 **기준 저장 · 다음 수집부터 적용**을 눌러야 반영된다. 저장 전 이동·새로고침은 수정 내용을 잃을 수 있어 확인한다.
- 새 채널은 이름, 홈페이지 주소, 공개 RSS·Atom 주소로 추가한다. 추가 채널은 최대 20개다. 기존 기본 채널 15개는 별도다.
- **수정안에 채널 추가**는 화면의 수정안만 바꾼다. **기준 저장 · 다음 수집부터 적용**까지 눌러야 서버 기준에 반영된다.
- 추가 채널의 기본값은 수집 켜짐, AI 키워드 필터 켜짐, 실행당 최대 30건, 게시 근거 꺼짐이다. 뉴스레터 선정에 포함하려면 관리자가 게시 근거를 켠다.
- 삭제도 기준 저장 후 다음 수집부터 적용된다. 이미 발행된 기사·카드 원고는 삭제하지 않는다. 삭제한 기본 채널은 **삭제한 기본 채널 다시 추가**에서 복원할 수 있다.
- 새 채널 입력 중이거나 저장하지 않은 기준이 있으면 페이지 이동·로그아웃 전에 확인한다. 새 채널 정보는 수정안에 추가하거나 비운 다음 기준을 저장한다.

## 지원 주소와 수집 제한

일반 홈페이지를 RSS로 자동 변환하지 않는다. 신규 YouTube·X·Reddit 계정 연결도 이 기능의 범위가 아니다. 기존 API 채널은 종전의 연결 설정을 사용한다. API 수집 주소는 해당 서비스의 지원되는 공식 조회 경로만 허용하며 검색 쿼리와 인증 정보를 붙일 수 없다. Hacker News는 새 글·인기 글 등 목록, Reddit은 서브레딧과 new/hot/top/rising, X는 recent/all을 지원한다. YouTube는 기존 search 경로를 사용한다. 실제 API 이용 범위는 연결된 계정 권한에 따른다.

추가 채널과 수정하는 기본 피드 주소는 로그인 정보·비밀키가 없는 공개 HTTPS RSS/Atom만 지원한다. IP 주소, 내부 호스트, 별도 포트, 사용자명·비밀번호, 비밀값 쿼리와 중복 피드 주소는 거부한다. 정책은 공개 읽기 API를 사용하므로 비공개 피드 주소를 입력하지 않는다.

추가 채널과 주소를 수정한 기본 피드는 피드·홈페이지에 등록된 정확한 호스트의 기사만 수집한다. 주소를 바꾸지 않은 기본 채널은 기존 허용 호스트를 유지한다. API 채널의 홈페이지 변경은 인증 요청을 보내는 서버 주소를 확대하지 않는다. 다른 도메인으로 이동하는 피드, 로그인 필요·접근 차단·지원하지 않는 응답은 수집 실패 또는 항목 보류로 남는다. 등록 시 네트워크 연결 성공을 보장하지 않으며, 다음 외부 수집의 출처별 결과를 확인한다.

추가 채널과 주소를 수정한 기본 피드의 피드·본문 요청은 프록시·쿠키·인증 헤더 없이 실행한다. 모든 DNS 응답의 공인 IP 여부를 검사하고 검증한 IP로 직접 연결하면서 원래 호스트의 TLS 인증서를 확인한다. 리다이렉트도 호스트·DNS를 다시 검증한다. 응답 크기·요청 시간·리다이렉트 횟수와 XML 선언을 제한한다.

## 데이터와 저장소

정책 형식 v3는 기존 v1·v2를 읽어 같은 기준·저장 버전을 유지하며 변환한다. 기본 채널의 주소 변경은 source_urls, 추가 채널의 주소 변경은 custom_sources에 보관한다. 추가 채널 정의와 채널 규칙의 일치를 화면·서버·수집기에서 검증한다. 알 수 없는 필드·규칙은 거부한다.

삭제한 채널의 미게시 후보는 `retired_events`에 분리해 보존하며 게시 판단에서 제외한다. 과거 출처 점검 기록은 삭제 표시와 함께 남기고 현재 실패 집계에서 제외한다. 기본 채널을 복원하면 현재 기간·키워드·게시 기준으로 후보를 다시 판단한다.

서버 저장소 연결이 필요하다. 저장소가 없으면 수정안은 작성할 수 있지만 저장 버튼은 비활성화되며 실제 수집에는 적용되지 않는다. 연결 절차는 [카드뉴스 관리자 운영 문서](CARD_NEWS_ADMIN.md)의 ‘뉴스레터 설정 저장소 연결’을 따른다. 실제 운영 저장소 저장 성공은 연결 후 별도 확인이 필요하다.
